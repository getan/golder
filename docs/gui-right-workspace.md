# GUI 右侧工作区设计

本文记录 GUI 右上角功能入口和右侧工作区的交互约定，便于后续修改布局时保留用户意图与会话生命周期。

## 目标

- 保留对话区的可用宽度，不让 Terminal 与其他右侧面板分别嵌套、反复挤窄对话。
- 同时观察最多两个自动化功能；有更多功能时可手动选择而不丢失其后台状态。
- Files 和 Changes 由用户主动打开，在工作区上层查看，不让自动化事件抢走当前操作。

## 布局与选择

对话区与右侧工作区左右分栏。工作区空闲时不占宽度；有一个自动化视图时占满右侧，有两个时上下排列。横向宽度和上下分隔比例可以拖动，并在本次 GUI 运行期间保留。

横向拖动要为对话输入区保留至少 320 布局单位，并为右侧工作区保留至少 180 布局单位；计算时计入导航栏和项目侧栏。窗口较窄或字体缩放较大时，项目侧栏可先收窄，避免遮挡发送/停止按钮。模型名称过长时在按钮内省略，完整名称可通过提示查看。

自动化视图的默认优先级及上下顺序是 **Computer Use > Browser > Terminal**。三个视图都请求打开时，默认展示 Computer Use 和 Browser，Terminal 仍保持请求状态但暂不展示。用户点击被遮住的 Terminal 图标后，展示 Computer Use + Terminal，Browser 暂时让位；再点击 Browser 则切回 Computer Use + Browser。点击当前可见的功能图标或面板关闭按钮执行其原有隐藏/关闭操作，空出的区域由仍请求展示的功能补位。

手动选择只决定当前可见组合，不关闭被替换的功能。新功能自动请求展示时重新按默认优先级选择；已有功能的后台事件不会反复覆盖用户的手动选择。Terminal 的 Agent `focus` 若受上层视图或优先级遮挡，会返回明确错误，不假称已聚焦，也不抢走用户正在看的抽屉。

## Files 与 Changes

Files 和 Changes 互斥，作为覆盖右侧工作区的用户视图展示；打开其中一个不会终止、关闭或重置下层的 Computer Use、Browser 或 Terminal。切换或关闭 Files 保留未保存编辑内容，切换项目或会话等已有的防丢失保护仍然适用。关闭 Changes 会取消进行中的 diff 请求。

当用户查看 Files / Changes 时，新到达的自动化视图只更新后台状态，不自动盖住用户视图；若发现多个浏览器，用户可稍后通过 Browser 图标选择。Computer Use 需要用户确认目标或授权时仍可显示必要的确认界面。关闭抽屉后恢复当时的自动化组合与分隔比例；也可直接点击某个下层功能图标关闭抽屉并展示它。

## 图标与生命周期

- 顶部功能按钮默认无方块底色，悬停时显示底色，键盘焦点保留轮廓。当前展示的功能使用强调色及短线；已打开但被遮挡或隐藏的功能使用次要色及短线，并在提示中标记 hidden。
- Changes 标题栏使用与 Files 一致的刷新和关闭图标，并提供可访问名称和提示。
- 暂时被布局或 Files / Changes 覆盖不会关闭浏览器预览连接、终端进程或 Computer Use 会话，也不会改变授权。**Computer Use 在隐藏、被覆盖或切换会话后仍可继续操作**；用户可通过打开 Computer Use 并选择 Pause / take over 或 Stop 来暂停/停止。重新显示面板不会自动恢复显式暂停的会话。
- 显式关闭 Browser 预览会释放该 GUI 预览连接，但不等同关闭浏览器进程；隐藏 Terminal 不结束 pane。关闭终端 pane、停止 Computer Use 和退出 GUI 仍遵循各自的确认与生命周期规则。

## 验证范围

自动化测试覆盖优先级、手动切换、自动补位、抽屉覆盖和恢复、未保存文件、diff 取消、Agent 聚焦，以及横向和纵向分隔线。真实桌面上的终端输入、浏览器画面和窗口尺寸变化仍需要使用已安装的原生依赖进行手动验证。
