# v1.5.48 — An icon, and an honest Gatekeeper note

## The app has an icon

`gui/resources/icon.png` is a 16×16 pixel-art mark — a white panel with a
stepped chamfer, a dark chevron and a gold cursor — scaled to 1024×1024 with no
interpolation, so every edge stays on the pixel grid.

It is generated, not hand-edited:

```sh
cd gui
go run ./tools/mkicon -o resources/icon.png
```

`mygo build` turns it into `AppIcon.icns` and references it from the bundle's
`Info.plist`. Until now the resources directory held no `icon.png`, which is
why a packaged build showed the generic blank icon.

## Why the download still says "Apple cannot check it"

That message is not about the icon or the packaging: it means the app is signed
but **not notarized**. macOS attaches a quarantine attribute to anything
downloaded, and Gatekeeper refuses a quarantined app it cannot check with Apple.

Two outcomes, no third:

- **With a Developer ID and notarization** the app opens on any Mac by
  double-click. The workflow does this when `MACOS_SIGNING_IDENTITY`,
  `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `APPLE_ID`, `APPLE_APP_PASSWORD` and
  `APPLE_TEAM_ID` exist.
- **Ad hoc signed** (today's default) it opens on the machine that built it; on
  another Mac the person allows it once:
  - macOS 15 Sequoia and later: double-click once, then **System Settings →
    Privacy & Security → Open Anyway**. Right-click → Open was removed as a
    bypass in Sequoia.
  - macOS 14 and earlier: right-click → **Open** → **Open**.
  - From a terminal: `xattr -dr com.apple.quarantine "/Applications/Golder GUI.app"`.

Zip, DMG and Homebrew casks all carry quarantine, so no packaging change avoids
this. Notarization is the only fix that makes a plain double-click work
everywhere.
