# v1.5.56 — Race-safe provider wire cache

The v1.5.55 release and GUI package workflows succeeded, but the Linux race job
found a concurrency gap in an existing provider test path: an adaptive fallback
could finish recording the wire that served a request while the next test reset
the package's lazy cache initializer.

The cache map was already mutex-protected; the `sync.Once` initializer was not
covered by the same mutex during test reset. Initialization and reset now share
`wireCacheMu`, preserving runtime cache semantics while removing the concurrent
read/write window.

Validation includes the previously racing fallback tests repeated under the
race detector, a full provider race run and the complete repository race suite.
v1.5.56 also contains all v1.5.55 GUI changes: managed Lark Helper update and
rebinding, exact-socket Browser auto-reveal, neutral Send/Stop controls,
outlined monochrome icons and the supersampled App icon build path. Linux
container preflight remains suspended by user request.
