# v1.5.55 — One-click Helper updates and dependable Browser reveal

## Update the Helper without rebuilding configuration

Settings now displays three separate versions for the managed Lark extension:

```text
Bundled
Installed latest
Active Source
```

When the active Source does not use the helper bundled with the GUI,
authorization, connection testing and approval are blocked and **Update
helper** is offered. One click verifies and installs the bundled executable,
rebuilds command/setup around that exact package, and leaves the replacement
Source disabled and unapproved for explicit review.

The update preserves official CLI paths, App ID, domains, Project host, the
named App Secret reference and the source-scoped login HOME containing tokens
and DPoP state. It does not reset server authorization or remove the previous
managed package. After updating, the person only needs to click **Approve &
enable** before verifying the retained login.

The Controller enforces the same version boundary, so stale UI state cannot run
an old helper. Replacing a Source also revokes the old runtime object's enabled
flag and both session and persisted approvals.

## Open the exact Browser drawer automatically

Browser discovery in the GUI now uses the browser tool's validated metadata
boundary, including short runtime sockets used by long project paths. A
completed `browser open` carries its exact socket into the pending reveal state.
With several live browsers, the matching instance opens directly; if discovery
races startup, the request remains pending for the next refresh instead of
falling back to a manual button click.

## Neutral controls and a smooth App icon

The approval hand is now an outlined, hollow, theme-colored SVG. Send `↑` and
Stop `■` both use a neutral gray palette; the glyph alone communicates the
action.

The App icon keeps its white panel, dark `>` and gold `-`, but replaces the old
16×16 staircase with geometry rendered at 4× and downsampled to an antialiased
1024×1024 image. The GUI release workflow regenerates it before every platform
build, keeping the asset reproducible.

## Validation

Local validation includes formatting, build, vet, the full race suite, focused
managed-package/GUI/Browser/icon tests, Linux arm64 and Windows GUI cross-builds,
the GUI no-tuios dependency boundary and workflow YAML parsing. Tests verify
version detection, exact executable rebinding, approval revocation across
restart, private login and named-credential preservation, exact-socket Browser
selection, neutral control colors, outlined SVG geometry and antialiased icon
pixels. Linux container preflight remains suspended by user request. No live
Lark OAuth or real Chromium interaction was performed.
