# v1.5.51 — Approval context and desktop diff readability

## Preserve recent authorization context

The reviewer now prioritizes recent user messages within its bounded transcript
and can include up to eight recent requests instead of three. This helps retain
an explicit deployment request when later tool output or follow-up messages
would otherwise crowd it out. The reviewer still decides the actual action;
older, compacted or truncated history may not be available.

## Bound Git push envelopes

An ordinary single Git push to a locally resolved SSH or HTTPS remote can now
use a one-call outside-sandbox envelope on its first attempt, including a
cross-repository `git -C` invocation. The gate binds the effective destination
and pre-push hook, and checks them again before execution. This allows Git's
host authentication without first spending a sandboxed network attempt.

Force pushes, deletion refspecs, opaque or mixed remotes and unbound hooks do
not receive the ordinary automatic rule. In ask mode the person still decides.
For a fallback sandboxed push failure, matching structured prior-result evidence
is supplied to the reviewer; a refused escape is not silently rerun contained.

## Wrapped unified desktop diffs

The Changes drawer now shows one unified column, with added and removed lines
in the same view, and wraps long lines. This avoids an empty old-file half for
new files and reduces horizontal scrolling in the narrow review panel. Lazy
single-file loading and its existing size limits remain unchanged. Automated
tests cover modified, added and deleted patches at a narrow window size; a real
desktop visual check remains useful.

## Validation

Local preflight includes formatting, build, vet, race tests and a CGO-free
Linux arm64 cross-build. Linux container preflight remains suspended by user
request; no actual GitLab push or remote deployment was performed as a test.
