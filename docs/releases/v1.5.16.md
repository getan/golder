# golder v1.5.16

## Responses reasoning continuity

Preserve finalized original reasoning from `response.output_item.done` when
the terminal response omits it, repeats only an empty shell, or never arrives
before a clean stream end. Recovery deduplicates by item identity and retains
the known ordering without rewriting opaque fields or signatures.

Replay provenance now follows the requested model, not a gateway's different
resolved backend label. Both `reasoning_text/text` and `thinking/thinking`
content are recognized. Provider/model isolation and contiguous tool-call
replay remain intact. UI thinking summaries do not replace protocol state;
missing original state in an old session cannot be reconstructed by upgrading.

SDK-level streaming → session serialization → tool-result continuation tests
cover the previously missing paths. These are deterministic fixtures, not a
claim that every gateway or the user's failing production request was tested.

## Safe diagnostics for SSH Tab exits

`GOLDER_TUI_TRACE` (alias `GOLDER_STARTUP_TRACE`) now adds fixed control-key
classes, completion begin/apply/end, geometry and menu counts, explicit quit
intent, classified I/O/program errors and content-free panic frames. Panics
are rethrown, not swallowed; no additional signal handlers alter HUP/TERM/INT.

Responses diagnostics report per-attempt capture/replay counts, provenance
decisions, placeholder selection and a classified thinking-replay rejection.
They do not log prompts, typed text, opaque reasoning, signatures, arguments,
model identifiers or upstream error bodies. Normal stderr is separate and
must be reviewed/redacted before sharing.

See [the field debugging runbook](../debug-ssh-tab-exit.md) for collection
commands and the report to return from the affected machine.
**The reported `/pro` + Tab SSH logout has not been reproduced or declared
fixed.** Local Linux OpenSSH controls stayed alive after Tab and exited only
after an intentional Ctrl+D; root, the production bastion and existing-session
differences still require field evidence.

## Controlled terminal compatibility and workspace fixes

On macOS, controlled pane children can configure only their own allocated
PTY and verified controlling-terminal alias. No blanket terminal ioctl grant
is introduced; input injection and line-discipline mutation remain denied.
See [the terminal-control boundary and tests](../workspace-pane-terminal-control.md).

This release also includes the workspace welcome/config-discovery latency
fix, optional Linux extension cleanup handling, and the CLI-backed Lark MCP
plugin already committed since v1.5.15. Existing extension admission and
credential boundaries are not bypassed.

## Dependency pins and validation

Both dependency pins already resolve to their latest published default-branch
commits, so neither dependency is republished without changes:

- tuios-mini `v0.10.16`: `771f2b9b2262ea5b731dd21a31b3caf6ddedd0a3`.
- kitty-browse `v0.2.3`: `b2bf2bc94a6a03d20369b1d146c06294d0a4e4f4`.

Release gates are local build, vet, race tests (including the shared terminal
decoder), formatting and Linux arm64 cross-compilation. Inherited host/JEV/
OAuth overrides are cleared or normalized for tests, not changed for users.
The Linux container was explicitly enabled for targeted native diagnostics
and real SSH checks in this investigation; **full Linux CI preflight remains
suspended**. Targeted runtime tests are not a claim that the full Linux suite ran.

Use the new binary on the affected machine: setting a trace environment
variable on an older build cannot produce these new diagnostic events.
