# golder v1.5.18

## Follow-up to v1.5.17

The first rerun repaired the original nightly failures, but the full Linux
race job then exposed an additional popup exit-status race in tuios-mini.
Previously published v1.5.17/v0.10.17 tags are preserved; this is a new patch,
not a force-moved release.

Golder now pins tuios-mini **v0.10.19**. A `new-window --wait --keep-open`
reply no longer eagerly reads a retained signal while its callback writes
it. It reads the live PTY's protected signal when available, otherwise waits
for the retained result's publication barrier. The complete local session
race suite and 100 repetitions of the existing real-daemon/PTY regression
passed. kitty-browse remains on its unchanged latest tag, **v0.2.3**.

## Golder CI fixture correction

The Linux input-library test tried to cancel an already-blocked syscall
`Read`, rather than the `Poll` operation used by the input loop. After a
nonfatal 100ms timeout it reassigned variables still captured by its worker;
that produced a test data race and stole one byte from the next phase.

The fixture now uses the Poll-then-Read contract, passes the reader by value,
returns the result through a channel, stops on timeout, and closes both
readers' polling resources. Cancellation and all five input bytes remain
asserted. It passed 1000 local race repetitions and 1000 Linux native
repetitions. No production parser, input filtering or permission change is
included.

## VT fuzz contract correction

The later 30-second-per-target Fuzz rerun found a new
[`FuzzKittyHeader` case](https://github.com/getan/tuios-mini/actions/runs/40738060821)
in the independently pinned VT submodule: `f=100;0`. The whole-struct oracle
also compared private PNG payload-prefix bookkeeping (nil versus an empty
slice), although public control keys and observable replies agreed.

As approved, the corrected equivalent campaign lives in mini's root-module
`internal/vtcontract`, leaving the upstream-owned VT runtime files, module
path and v0.2.0 pin untouched. CI replaces only this campaign's location.
All original seeds, the failure artifact and protocol assertions are retained;
the comparison checks every exported control key, not private payload state.
A guard mutates each of the 26 public control fields to ensure a real mismatch
still fails. The old comparison failed on the corpus before correction; the
new target passed race checks and 5,262,173 mutations in a local 60-second run.

This VT failure and Golder's reader fixture race were test-layer defects, not
observed production input changes. The earlier tiny-pane rendering overflow
and popup exit-status race can affect real use and are also fixed. None of
these measurements proves the entire cause of a production one-minute stall.

The SSH reduced-rendering and terminal-startup recovery changes from v1.5.17
are retained. Full Linux container preflight remains suspended; targeted
native Linux checks and upstream GitHub CI are reported separately.

## CJK input after a split escape prefix

Chinese typed through an IME could disappear from the composer while ASCII kept
working. If the terminal delivered `ESC [` or `ESC O` in one read and the rest
later (a mouse report, a query reply, an ordinary keystroke racing the frame),
the framer treated every following byte as frame payload until an ASCII final
byte (0x40-0x7e) arrived. A UTF-8 lead byte is never a CSI/SS3 final byte and no
idle timer runs while a frame is pending, so every CJK character stayed
buffered. The next ASCII keystroke released the whole backlog, which is why the
symptom looked intermittent.

`input_frame.go` now ends a CSI/SS3 frame at a valid UTF-8 lead byte
(0xC2-0xF4), which can only be typed text; those bytes decode normally.
Invalid bytes such as 0xff still stay inside the malformed frame, so a corrupt
report's tail is never typed, and X10's three raw payload bytes are consumed
before the check. The regression covers CJK and emoji after a split CSI and
SS3 introducer at every split position, plus recovery from an oversized frame.

## Third-party fixes pulled in

- tuios-mini **v0.10.19**: the VT differential fuzz campaign moved to the
  fork's own `internal/vtcontract` (public control keys only, corpus and all
  protocol assertions kept, 26-field mutation guard), the Fuzz workflow runs
  Go 1.27.3 to avoid the Go 1.26 `-fuzztime` false failure
  ([golang/go#75804](https://github.com/golang/go/issues/75804)), and a daemon
  test no longer races its own prompt check.
- kitty-browse **v0.2.4**: the headless host's allocator context no longer
  derives from the caller's startup deadline. Golder bounds `Start` with 45
  seconds; that deadline used to kill every later CDP call, so a screenshot
  taken afterwards returned 500 `context deadline exceeded`. Cancelling the
  caller's context still stops the host, and shutdown still releases Chromium.

Both dependencies' GitHub CI is green on the tagged commits: mini's Fuzz (all
16 jobs, Go 1.27.3) and Go unit tests (Windows, Linux and the full race job),
kitty-browse's tests including the new late-screenshot regression. Golder's
own full race suite passes against the published tags, with the vendored input
packages included (83s), as do Linux arm64 and Windows amd64 cross-builds.
