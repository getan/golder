# v1.5.67 — Conversation-local browsers and desktop workflow fixes

This patch release includes every workspace change since v1.5.66.

## Browser isolation without losing logins

- Pin **kitty-browse v0.2.11**. One dedicated Chromium/profile owner shares
  project login state, while each GUI or TUI conversation gets its own socket,
  browser identity, tab collection, selection and lifecycle.
- A private operator connection carries person-originated input separately from
  model automation. Routine default-profile opens add no new consent prompt;
  existing network/runtime review, named-profile consent and verification-pause
  rules remain in force.
- Closing one view does not close another. Frontend heartbeat expiry reclaims
  crashed views; the final view's idle shutdown retains the persistent profile.
- Close pre-upgrade standalone browser processes once before opening shared
  views. Golder will not kill a process to take its profile lock.

## Desktop workflow

- Hide routine approval verdicts outside debug mode, preserve exact approval
  identity/context, and compact transcript rows and repeated patch output.
- Browse the same prompt history as the TUI with composer Up/Down, restoring
  drafts and preserving multiline caret navigation. Queue follow-up messages
  during a turn without interrupting the active tool batch.
- Improve macOS desktop-window discovery, including windows on other desktops,
  and collapse SVG source behind its preview.
- Refresh README GUI screenshots and architecture documentation.

## Dependencies and validation

Golder resolves published kitty-browse v0.2.11 with `GOWORK=off`; no local module
replacement is required. tuios-mini remains pinned to the latest published
module tag **v0.10.45**; its workspace has no pending changes.

Validation passed with the published dependency and `GOWORK=off`:

- `go test -race -timeout 6m ./...`
- `go build ./...`, `go vet ./...`, `go mod tidy -diff` and formatting checks
- Linux arm64 and Windows amd64 cross-builds
- kitty-browse's browser-free unit/race suite and helper-process readiness and
  idle-cleanup tests

Real Chromium GUI/TUI end-to-end validation remains deferred by request. Linux
container preflight remains suspended; cross-compilation is not a Linux runtime
test.
