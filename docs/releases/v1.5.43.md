# v1.5.43 — Reliable Git push retries and browser diagnostics

## Git push retry behavior

- A `git push` that exits non-zero inside the file sandbox now receives exactly
  one outside-sandbox retry instruction. Detection uses the parsed command and
  exit status, not platform-specific or localized stderr such as `Device not
  configured` or `permission denied`.
- Pushes targeting another checkout use `git -C <repo> push ...` rather than
  `cd <repo> && git push ...`. The literal form lets the consent gate resolve
  the effective remote from local Git configuration before review.
- The retry requests `network:on` and `sandbox_permissions=require_escalated`.
  Under auto mode an allow/confirm verdict produces `Direct=true`,
  `Sandbox=false` and `Network=true`; under ask mode the person makes that
  one-call decision.
- If the escape is refused, remains contained or the outside retry still fails,
  the agent stops instead of repeating the same request. A non-zero exit is not
  treated as proof that no remote refs changed because a multi-ref push can
  partially succeed.
- Tests cover the reported `cd ../annotation-workbench && git push origin main`
  shape with arbitrary failure text, the normalized `git -C` remote resolution,
  and an approved HTTPS auto-mode retry reaching the direct execution envelope.

## Browser login compatibility diagnostics

- `browser status` reports the controlled profile and browser runtime plus the
  configured and observed proxy modes without opening Chromium cookie storage.
- Guidance distinguishes the shared project-default identity from separately
  named profiles and records the macOS basic-password-store/mock-keychain
  compatibility invariant.
- Diagnostic output avoids exposing cookies, authorization values or other
  credential-shaped details.

## GUI architecture documentation

- `docs/gui-architecture.md` evaluates Wails, Fyne, Gio and `webview_go` for an
  optional desktop client without Electron or a bundled Chromium runtime.
- The recommended design adds a separately built `golder-gui`, keeps the
  existing CLI/TUI/workspace behavior intact, and reuses the Go runtime,
  permission gates and session store through a thin application controller.

## Validation

Local formatting, build, vet, race tests and Linux arm64 CGO-free cross-build
checks pass. The Linux container runtime preflight remains suspended by user
request and is not claimed for this release.
