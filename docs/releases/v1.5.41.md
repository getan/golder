# v1.5.41 — Reliable SSH pane tasks and shared browser control

## SSH and multiple panes

- `tuios run` accepts `script` for large/multiline POSIX shell tasks through an
  existing SSH terminal. The server needs only its ordinary system commands,
  not tuios, a preinstalled helper, Python, root access or a new service.
- A small setup precedes one batch of short numbered base64 comment lines.
  The complete payload must pass sequence, length, SHA-256 and syntax checks
  before any script command starts. Queued payload remains inert shell comments
  if the receiver/SSH exits. Explicit/detected remote scripts require an SSH
  Linux context and reject the local-kernel fallback.
- Ready/completion waits use daemon events and pane-close subscriptions, not
  capture polling or sleeps. Different panes can progress concurrently while
  same-pane input remains serialized and queued permissions are rechecked.
- Results identify request, source pane, target pane and available name/host
  hints in model-visible text. Missing OSC completion marks no longer cause a
  potentially executed command to be sent again; interrupted outcomes are
  explicit and non-retryable.

### Compatibility and limits

`script` runs in a noninteractive POSIX child shell with stdin closed, preserving
normal exported variables and the original umask. It does not persist `cd`, shell
variables or aliases in the interactive parent. Leave a blank shell prompt first.
Detected/explicit SSH tasks must use `script`, not the short interactive
`command` path. Raw `send`/`press` remain unverified interactive input.

Scripts are limited to 1 MiB; short commands to 2048 bytes. Same-kernel SSH targets
and hosts that remove `SSH_CONNECTION` or hide Linux boot identity are rejected
conservatively. This is not host attestation, transactional file editing or an
exactly-once guarantee. Use staged files, expected hashes and atomic rename for
important edits; inspect unknown outcomes instead of retrying automatically.
See [the SSH pane guide](../tuios-ssh-scripts.md).

## Browser sharing

- Manual page focus and ASCII/CJK/Backspace input work after address editing,
  including nested/shadow editable elements.
- Optional project-scoped named profiles remember login state outside the
  repository. Each agent session needs exact human consent before using them;
  another agent does not automatically inherit signed-in page access.
- The footer distinguishes observation, active mutation, completion, input
  conflict and verification pause without a new takeover/lease system.
- Clear verification/rate-limit signals pause future automated mutations.
  Manual handling and observation remain available; explicit continuation
  (Ctrl+G or human-confirmed `resume`) never replays old actions.
  See [the browser sharing guide](../browser-sharing.md).

## Dependencies and validation

- `github.com/getan/kitty-browse`: **v0.2.7**.
- `github.com/getan/tuios-mini`: **v0.10.39**, unchanged.
- Local race/static/build checks, corrupted/missing/reordered frames, lost
  receipts, independent panes, and a disposable real daemon/PTY transferring
  80,000 UTF-8 bytes at 24 columns are covered. Real remote Linux/unstable-WAN
  acceptance has not been claimed.
- The opt-in Chromium Back/Forward history integration test has an unresolved
  intermittent CDP `-32000` observation; this release does not claim every
  opt-in Chromium integration test passes.
- Local Linux container preflight remains suspended by user request; cross-build
  checks are not a substitute for Linux runtime testing.

## Upgrade

Update Golder normally and restart the workspace/agent to load the new embedded
browser implementation and tool schema. Existing SSH servers need no installation
or configuration change. A website may still expire or revoke a saved login.
