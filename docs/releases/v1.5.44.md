# v1.5.44 — Exclusive Agent control for existing tuios panes

## Choose an Agent from the pane

- Every top-level Golder session running in tuios registers a daemon-scoped
  Agent ID plus project/role label, conversation ID, pane ID, workspace,
  permission mode and live state. Heartbeats expire crashed registrations; a
  conversation switch or Agent exit unregisters it and removes its leases.
- The tuios pane context menu shows the current controller and only eligible,
  live Agents in the same session/workspace. The person can grant control for
  the next action or this Agent conversation, and can revoke it there.
- `/pane agents`, `/pane status`, `/pane allow-agent <full-pane-id>
  <one-call|session>` and `/pane revoke-agent <full-pane-id>` provide a direct
  user-authored alternative in the selected Agent's composer.

## Exclusive lease and transfer semantics

- A full pane ID has at most one writer lease. Concurrent claims have one winner;
  another Agent sees the controller rather than gaining overlapping authority.
- Transferring control requires a second tuios confirmation that names both
  Agents, or an explicit user-authored `--transfer` slash command. The previous
  Agent's queued operation revalidates the shared lease immediately before the
  daemon send and fails if ownership changed.
- One-call leases are atomically consumed by the next input or pane mutation.
  Session leases end on revoke, Agent/conversation exit, pane close, daemon
  replacement, workspace move, a protected Agent/browser/approval transition,
  or a changed SSH host/foreground identity.
- Dynamic tuios menu actions carry a private direct-selection token and are not
  recorded into replayable project tapes. A repository tape or keybinding cannot
  forge operator authorization by reproducing an action string.

## Review and containment remain separate

- A lease avoids repeated `host_control:true`; it does not approve any command.
  Each `run`, `send`, `press`, focus, move, rename or close still follows the
  ordinary reviewer and static safety floor.
- Existing local and SSH shells remain outside Golder's OS file sandbox. A call
  requiring containment cannot spend a lease. SSH input still needs reviewed
  network access, and reliable remote work still uses verified `run + script`.
- The model-facing `tuios claim` action requires ask mode and an exact human
  confirmation bound to daemon, session, full pane ID and remote/foreground
  identity. Auto and full-access modes cannot invent this standing authority.
- Agent panes, approval surfaces and browser panes remain non-claimable through
  terminal input. Browser work continues through the browser tool.

## Reviewer and state fixes

- First-party classification now reviews `run.script` as the actual shell
  effect, rejects missing or simultaneous command/script bodies, and forwards
  `host_control:true` reads/focuses to contextual review instead of granting a
  fixed local allow.
- Broker-created shells cannot turn one-call outside-path access into a reusable
  pane. `tuios list` reports control origin, owner, scope, sealed state, current
  input eligibility and eligible Agent candidates.
- Golder depends on tuios-mini v0.10.42 for the operator pane-menu integration
  and atomic Windows registry locking.

## Workspace pane admin default

- Golder's embedded workspace now starts panes with `read`, `write`, `fan` and
  `admin`, so tuios's **Toggle admin** action is on by default. This lets a pane
  create windows outside its startup folder without a first manual toggle.
- Set `GOLDER_WORKSPACE_PANE_GRANTS=read,write,fan` before starting a workspace
  to keep admin off by default. The focused-pane toggle can still add or remove
  admin without dropping the other grants.
- Pane admin governs calls through tuios. It does not bypass Golder's per-command
  review, file boundary, network review, or the operator-only Agent lease rules.

## Cleaner Extensions and Skills navigation

- `/extensions` now lists tool-bearing MCP, CLI and legacy RPC sources only.
  Skills remain under `/skills`, including preview, use, enable and disable.
- A bare `/` popup and `/help` show the `/skills` entry point rather than
  duplicating every installed Skill under Extensions. Typing a Skill's prefix
  still completes it, and its direct slash command remains fully invocable.
- The line REPL, full-screen TUI, text output and JSON extension inventory follow
  the same split.

## Validation

Coverage includes concurrent multi-Agent claims, explicit transfers, operator
revocation of another Agent, queued-send revalidation, one-call consumption by
input and non-input mutations, exact full-ID routing, Agent/approval/browser
refusals, SSH host changes, sealed helper panes, direct-menu provenance and
`run + script` reviewer routing, plus the workspace admin default and
Extensions/Skills catalog split. Local formatting, vet, race tests, builds and
Linux arm64 CGO-free cross-builds pass. tuios-mini v0.10.42 also passes its full
multi-module CI matrix, cross-platform vet, Windows tests, lint and vulnerability
scan. The Linux container runtime preflight remains suspended by user request
and is not claimed for this release.
