# v1.5.53 — Agent-opened native browser drawer

## The desktop Agent now has a browser tool

The Bitmap Browser Surface previously attached only to an already-running
owner-only browser socket. Because the GUI deliberately embeds neither tuios
nor a second full `golder` CLI, a fresh desktop session did not register the
`browser` tool and the model correctly reported that no browser was available.

On macOS and Linux the GUI now configures a linked kitty-browse browserhost as a
native launcher before project tools are assembled. `browser open` starts an
installed Chromium on demand with the existing validated project profile,
socket, URL and ownership policy. The tool remains absent on platforms without
the Unix control-socket transport. Chromium is not bundled.

The GUI host currently refuses a configured browser proxy instead of silently
ignoring it; terminal-pane launches retain their existing reviewed proxy path.

## Browser and Changes use compact right-side actions

The title bar now uses icon-only `▤` and `🌐` actions with descriptive tooltips.
Changes and Browser drawers are mutually exclusive so they do not jointly
compress the transcript. When an Agent `browser open` completes, the GUI
discovers the new socket and automatically reveals the interactive right-side
Bitmap drawer. Mouse, keyboard, scroll, resize, tabs and committed IME input
continue through the typed browser-control API.

The Composer's narrow `☝` approval-mode mark is replaced by the fuller `✋`
hand while preserving its tooltip and behavior.

## Compatibility and validation

The native launcher is configured only by `golder-gui`; CLI/TUI browser-pane
behavior remains unchanged. Local validation includes formatting, build, vet,
the full race suite, focused GUI/native-browser/TUI tests, Linux arm64 and
Windows GUI cross-builds, and the GUI no-tuios dependency boundary. Linux
container preflight remains suspended by user request. A real installed
Chromium visual check remains an operator acceptance step.
