# v1.5.50 — Project-first desktop workflow and bounded Git review

## Projects now own Session working directories

The desktop sidebar follows an explicit project-folder model. Adding and
selecting a folder controls where **New session** runs; switching projects
rebuilds the cwd-bound tools, prompt, trust, Extensions, memory and Git context
rather than merely filtering historical rows. Chats are shown under the selected
project by title and time, while Settings lives at the lower-left.

## The composer keeps its controls together

- `+` attaches images or small text files;
- the hand control selects approval mode;
- one model control selects both model and reasoning effort;
- Send changes to Stop in place while a turn runs.

Images are sent as multimodal content. Text attachments are limited to 1 MiB,
and every attachment is rejected before reading when it exceeds 20 MiB.

## Changes is repository-aware and lazy

Changes resolves the active Session's Git root and branch, then presents
Unstaged and Staged views with file status and line counts. Files or the entire
view can be staged and unstaged; rename operations include both paths.

Opening the drawer does not build a repository-wide patch. The changed-file
list is bounded to 2,000 entries, and selecting a row asynchronously loads only
that file. A newer selection cancels and supersedes the old request. Each patch
retains at most 2 MiB, with excess subprocess output discarded while the pipe is
drained.

## GUI credentials are encrypted at rest

Provider API keys and Lark App Secrets share one named-credential store:

```text
~/.golder/.credentials.yaml  AES-256-GCM envelope
~/.golder/.credential-key    random 256-bit local key, mode 0600
```

The implementation uses Go's cross-platform standard cryptography rather than
platform keychain commands. Legacy plaintext credential YAML remains readable
and is rewritten as ciphertext on the next save. A legacy `config.toml` literal
`api_key` is migrated when Provider Settings is saved. The repository ignores
both credential basenames as well as the complete `.golder/` directory.

Automatic unlock protects a credential file copied without its key; possession
of both files permits decryption, so both remain private state and are never
release assets.

## Synchronized TUI workspace frames

Inside Golder's own tuios-mini workspace pane, the TUI enables DEC 2026
synchronized output even when terminal capability queries are suppressed or
delayed. This addresses one source of partially redrawn rows; confirmation in
the reported Ghostty setup remains an operator acceptance check.

## Validation

Local validation includes full build, vet and race suites, focused GUI and
credential tests, and CGO-free Windows/Linux GUI cross-builds. Linux container
preflight remains suspended by user request and is not claimed here.
