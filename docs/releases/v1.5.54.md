# v1.5.54 — Reliable Lark authorization and monochrome GUI controls

## Reconcile the real Lark user state

The Lark device-code command can save a valid token and still exit non-zero
during a later cleanup or output step. Setup no longer treats that exit alone as
proof of failure: it runs `auth status --json --verify` and accepts an explicit
`identity=user, verified=true` payload even when the status process itself exits
non-zero.

Final verification performs a bounded sequence of read-only status checks for
command, network or service failures. An explicit bot, non-user or
`verified=false` response remains terminal and is never retried or converted to
another identity.

## Safe phase-coded setup failures

The helper and host share a closed setup failure vocabulary covering private
store preparation, application configuration, authorization start/poll,
verification, cancellation and timeout. The host validates phase/code pairs and
replaces every supplied message with canonical text. Raw stderr, device codes,
authorization URLs, tokens and App Secrets remain withheld; unknown codes fail
closed without being echoed.

The GUI clears an authorization URL on completion, failure, cancellation or
timeout, and only offers **Open authorization page again** while the matching
poll is active. Source state refreshes after both success and failure. Settings
now distinguishes **Application** configuration from **User authorization** and
warns when the GUI and managed helper versions differ.

## Monochrome controls and dependable Browser reveal

The approval hand and Browser globe are MyGo SVG icons colored by the current
theme instead of system color Emoji. They remain accessible by label and keep
their existing tooltips.

An Agent `browser open` records a pending reveal request. If the first browser
discovery races socket startup, the request survives and a later refresh still
opens the right-side Bitmap drawer automatically; no manual Browser-button click
is required.

## Validation

Local validation includes formatting, build, vet, the full race suite, focused
helper/host/GUI/TUI tests, Linux arm64 and Windows GUI cross-builds. Tests cover
poll failure followed by verified status, a transient verify failure, explicit
bot rejection, failure-event redaction, stale-URL cleanup and delayed browser
discovery. Linux container preflight remains suspended by user request. No live
Lark account authorization or real Chromium visual acceptance was performed.
