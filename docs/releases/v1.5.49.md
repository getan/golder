# v1.5.49 — Native GUI workbench, slim packages and managed Extensions

## The GUI and CLI now share configuration facts

The desktop launch path uses the same provider-facing overlay and credential
resolver as the CLI:

```text
explicit flag > config.toml > runtime default
explicit/config key > named credential > inherited provider environment
```

This fixes the case where a terminal session authenticated through
`credential = "openai-default"` while a Finder-launched GUI incorrectly reported
that OpenAI had no key. Settings edits Provider, model, base URL, protocol,
reasoning and named credentials without exposing values; the secret file is
atomically written at mode `0600`.

## A quieter, project-aware native interface

- Sessions show their working directory, group by project, filter across all
  projects and support rename, archive, delete, Markdown/JSONL export, reveal and
  copy-ID actions. Metadata changes preserve transcript ordering and obey writer
  locks.
- The top bar is reduced to project/session identity, active browser, Changes and
  Settings. `Cmd/Ctrl+K` opens the command palette.
- Send is a circular button inside the composer. It changes in place from the
  up-arrow to Stop while a turn runs; duplicate empty-state controls are gone.
- The existing native Markdown, thinking, tool, approval and DiffView rendering
  remains the conversation path—no terminal screen parsing was introduced.

## Interactive Browser Surface and optional terminal

The old read-only screenshot window is now a native interactive surface:

- Chromium frames render as MyGo Bitmaps;
- pointer, scroll, keyboard, committed IME text and viewport resize travel back
  through the owner-only browser control socket;
- native chrome provides address navigation, back/forward/reload, tab list,
  create, activate and close, plus opening the page externally.

The Golder-side surface is terminal-independent. kitty-browse v1 does not yet
publish raw pointer actions, so numeric pointer events currently use a closed,
non-user-script compatibility adapter; a future raw-input capability can replace
it without changing the GUI contract.

MyGo terminal remains only where a real PTY is useful:

- an explicit user shell, visibly outside Agent tool approval semantics;
- detachable takeover of an existing `bash` call started with `tty=true`.

The latter uses a non-owning, resizable exec-session connection. Closing the
window detaches without killing the process; `write_stdin`, timeout and interrupt
remain authoritative.

## Workspace is no longer part of the desktop product

The GUI no longer lists or attaches tuios workspaces and no longer packages a
second full `golder` CLI. tuios-mini remains the CLI/TUI pane/workspace product;
the GUI dependency graph excludes it.

macOS now publishes separate `darwin/arm64` and `darwin/amd64` packages. CI
rejects bundles containing a full CLI or Chromium and enforces a sub-50 MiB
per-architecture app. The measured stripped binaries are approximately:

```text
golder-gui    31.85 MB
golder-lark    8.07 MB
libghostty-vt ~2.00 MB
```

## Lark is managed without losing process isolation

Settings → Extensions provides the ordinary install/auth path while keeping
`golder-lark` an MCP stdio child:

1. the signed GUI carries an architecture/version-matched helper and checksum;
2. Install accepts only the closed first-party `lark` package ID, rejects
   symlinks and atomically copies verified bytes below
   `$GOLDER_HOME/extensions/packages/lark/<version>/`;
3. native file pickers select exact official `lark-cli` and optional `meegle`
   binaries;
4. App Secret goes to the named credential store, while TOML keeps only
   `${credential:lark-app-secret}`;
5. configuration remains disabled and unapproved until **Approve & enable**
   fingerprints the helper, dependencies and launch ceiling;
6. Lark and Project OAuth are separate, sanitized setup-event flows opened in
   the system browser;
7. Test initializes MCP/catalog only; reset and uninstall are distinct,
   separately confirmed operations.

Other configured MCP/CLI/RPC sources appear in the same page with endpoint,
trust, authentication, network/private-state/executable/tool facts. A disabled
source uses a two-click Enable → Confirm enable flow.

Pane Agent control is unchanged because the requested multi-Agent rules already
ship in v1.5.44/v1.5.45: same-session/workspace top-level candidates, exclusive
full-window-ID leases, explicit transfer, atomic one-call consumption, queued
input revalidation, read-only sub-agents and per-command review.

## SSH push authorization follows derived facts

In auto mode, a resolved SSH push whose transport, effective remote and local
pre-push hook are safely bound now retains the local `Confirm` grade. The gate
grants one binding-checked outside-sandbox invocation instead of handing the
fact back to a contextual reviewer that could choose containment—a mode in which
SSH credentials are deliberately unavailable.

A reviewer timeout/error is also distinguished from a denial: the transcript
says the push did not run and may be retried, while an actual `Contain` verdict
still explains that SSH cannot execute inside the file sandbox.

## Validation

Local validation includes:

```text
go test ./...
go vet ./...
go test -race ./internal/extensions ./gui/appsession ./gui/mygoui
```

Coverage includes credential precedence and private writes; session metadata;
browser coordinate mapping; TTY attach/detach; extension install checksum,
symlink/path/manifest rejection, version ordering and uninstall; source
fingerprint approval; secret-reference-only configuration; full GUI Lark
configure/enable/disable/uninstall lifecycle; and password-field non-disclosure.

Real-account Lark OAuth and business writes remain operator acceptance checks;
fixtures use no real credentials or remote business data. Linux container
preflight remains suspended by user request and is not claimed here.
