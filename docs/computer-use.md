# Golder Computer Use 方案

> 状态：功能开发中；以下为设计目标，不代表已完成首版验收。
>
> 首版平台：macOS、Linux、Windows；实施与验证优先顺序为 macOS → Linux → Windows。
>
> 范围：内置工具、单窗口会话、TUI/GUI 可视化与用户接管。

### 当前实现与限制

- 以下当前行为覆盖本文其余部分的早期设计表述：用户请求某个原生 App 后，唯一匹配的窗口可直接用于观察和控制；没有匹配窗口时，macOS 会查找并启动唯一匹配的已安装 App。多个 App 或窗口匹配时由用户选择；未找到匹配时不会猜测。会话仍绑定单个窗口，支持暂停、接管和停止。
- macOS：使用 Accessibility 和 ScreenCaptureKit；TUI 发布包与 GUI 均需启用 CGO。macOS 系统级辅助功能授权仍由用户在系统设置中授予，截图还需屏幕录制授权；权限属于实际运行 Golder 的宿主。真实桌面验收仍有待完成。
- GUI 切换对话或隐藏 Computer Use 面板只停止本地预览，不暂停或撤销已经授权的控制，也不把目标转交给新对话。显式暂停、接管及目标失效仍保留暂停行为；切回对话或重新显示面板不会自动恢复已暂停的控制。尚未完成的应用启动/窗口选择仍会取消，不能把它当作已授权会话继续。
- macOS 可能将屏幕采集权限显示为“屏幕与系统音频录制”；Computer Use 只获取所选窗口图像，不采集音频。辅助功能是独立的观察/控制权限；窗口歧义选择不是重复的系统权限授权，唯一匹配不要求手动再选。
- TUI 的 `/computer status` 只读取当前 Golder 进程的系统权限，不打开应用、不选择窗口，也不授予 Agent 控制权。GUI 的权限刷新显示同一进程的探测结果；重建或更新 ad-hoc 签名的 GUI 后，macOS 可能要求重新授权。
- macOS 窗口校验失败时区分权限、目标消失、屏幕窗口信息、AX 接口及窗口列表失败、几何信息不可读、不匹配、匹配不唯一和窗口数量超限。诊断只包含阶段、错误码和数量，不包含窗口标题、坐标或内容。无法证明唯一目标时仍拒绝输入；启动或切换失败同时报告当前进程权限，权限已授权也不表示窗口身份验证成功。
- macOS 在窗口位于其他 Space 时可能返回成功但为空的 `AXWindows` 数组。此时仅在公开属性 `AXMainWindow` 与 `AXFocusedWindow` 指向同一个、属于原进程的 `AXWindow`，且其几何唯一对应所选 CG 窗口时才接受只读回退；不会为此激活应用或切换桌面。非空列表中的歧义、不匹配、读取失败及权限错误不使用此回退。跨 Space 候选列表排除无法按窗口号和原进程重新解析的 CG 内部条目，避免将菜单等辅助记录误报为可操作窗口。
- macOS 应用启动或恢复期间，CG 与 AX 的窗口位置可能暂时不同；只对同一窗口的只读身份校验做短暂、有界重试，不重试启动、选择其他窗口或重放输入。几何暂时不可验证时拒绝动作并要求重新观察，不锁入暂停；身份改变或多窗口歧义仍拒绝并暂停。
- 当前实现没有全局人工鼠标/键盘活动监听；物理输入仍须验证焦点、遮挡、坐标及目标。能证明输入尚未发送时，短暂的目标验证失败只使旧观察失效；已派发但结果不确定的操作不重放。显式暂停/接管及明确身份变化、多窗口歧义仍保留暂停边界。
- macOS 按应用名查找时，先查找当前桌面，再对唯一匹配的已安装应用查找其他 Space 的现有窗口；不会为查找窗口主动切换桌面或反复启动应用。截图输入仅在目标已位于当前桌面、且同一应用没有其他不可见普通窗口时才可激活并抬起同一个已授权窗口，最多请求聚焦一次并有界等待，以降低 macOS 跳转到其他 Space 的可能。重新聚焦后复核画面，再通过命中/敏感控件检查；画面改变则重新观察。语义动作及本地预览不抢焦点；Pause / take over 或 Stop 会取消尚未完成的自动聚焦与输入。
- GUI 和 TUI 的本地预览是可中断、低优先级的：Agent 正在操作时跳过预览，Agent 开始操作时取消正在进行的预览；预览失败不会单独暂停控制。Resume 在原目标上有界重试瞬时只读验证，超时不伪装成目标已更换，也不会自动重放输入。
- TUI 人工接管保持简单：在操作 pane 按 **Ctrl+G**，顶部切换为“人工控制”，Agent 的控制和观察暂停；用户可单击预览，并在底部输入 `type 文字` 后按 Enter 将纯文本插入光标处（不会自动向 App 按 Enter，不使用剪贴板，输入内容不回显）。输入 `resume` 交还 Agent，不增加确认弹窗。接管会取消正在执行的 Agent 操作，人工输入必须等待同一操作锁；交还、暂停、关闭 pane 或停止都会使旧操作上下文失效，交还还会清空旧截图凭证。需要支持 Kitty 图形和 SGR 鼠标的终端，点击按终端单元格中心映射；不支持图形时仍可使用 `observe`、`click @eN` 和 `fill @eN 文字`。
- GUI 复用相同的 `OperatorView` 本地人工控制入口：点击 **Pause / take over** 后直接点击预览，在掩码文字框中输入并点 **Insert** 或按 Enter；**Resume** 交还 Agent。输入只使用原窗口的单次截图凭证，不接受留白区点击，不隐式向 App 提交回车。界面隐藏/会话切换取消待执行的本地动作并清空草稿，保持原会话的暂停/控制者状态；异步结果绑定会话、预览及输入代次，旧回调不覆盖新视图。相同画面重用位图；GUI 的 computer/browser 快照卡片默认全部折叠，只显示标题，不显示输出预览或额外展开按钮；点击标题或在会话区域按 Ctrl+T 切换，TUI 的三行预览保持不变。GUI 已有无窗口测试覆盖接管、坐标映射、文字、交还及导航取消，真实桌面输入仍需验收。
- macOS 人工点击与输入只来自本地 GUI 操作界面或经验证的操作 pane，不开放为模型参数：人可针对未暴露 AX 控件的画布操作，但仍检查原窗口身份、截图、焦点和点击点遮挡。人明确点击时仅在应用只有一个可重新解析的真实窗口时才允许激活其所在 Space；Agent 坐标动作仍不自动跨 Space。多真实窗口、画面已改变等情况仍拒绝，不盲目重放。
- macOS 模型侧新增 `type_text`，要求近期单次截图凭证以及可证明属于原窗口、已聚焦且非敏感的 AX 文本控件；它在光标处插入 Unicode 纯文本，不替换全部值、不使用剪贴板，也不隐式提交。未知画布、密码字段及不可证明的控件仍拒绝。原生输入按块检查同一窗口与控件，部分派发报告结果不确定而非“未派发”；聚焦失败则区分当前桌面不可见、无法枚举、真实同进程窗口信息不全及其他离屏窗口，并保留确定未派发的状态。以上新增路径有单元与原生判定测试，真实 Ghostty/tuios 鼠标映射及第三方客户端文字输入仍需桌面验收。
- 每个控制动作不再额外强制精确人工确认；常规权限模式和上下文风险评审仍生效，`read-only` 禁止控制。请求应用只接受应用名，不接受路径或系统句柄。
- Linux（amd64/arm64）：使用系统 AT-SPI2 枚举目标和执行语义观察、点击、文本替换。GUI 与 TUI 通过 XDG Portal 和 PipeWire 请求单窗口画面，并在本地预览经用户确认前禁止模型读取；需要支持稳定 PipeWire 序列号的 Portal 及相应 GStreamer 插件，不满足时拒绝采集。优先对目标子树中的控件执行语义动作；原生 X11 在 XRes PID、窗口几何、焦点、遮挡、输入状态及辅助功能命中可验证时，可向目标窗口定向发送受限合成按键和坐标事件，不使用可能被其他窗口抓取的全局 XTEST 输入。应用可以忽略合成事件，派发不代表动作已生效；Xwayland 不使用该路径。Wayland 的坐标点击、滚动及部分 Enter/Space/Escape 使用目标子树内的辅助功能动作或滚动条，其他按键和无法证明安全的画布输入仍拒绝：通用 Portal 键鼠注入不能证明事件只会到达授权窗口。终端不支持 Kitty 图形时可明确选择仅语义访问；Wayland 与 X11 均未进行真实桌面验收。
- Windows：使用 Win32 窗口身份校验，以及系统 Windows PowerShell 承载 UI Automation 的语义观察和动作。窗口预览代码先尝试通过 Windows Graphics Capture 的 `CreateForWindow` 获取单窗口画面，再以经捕获限制检查的 `PrintWindow` 作为回退；截图绑定的点击、滚动和按键在操作前重新检查画面、焦点、遮挡和敏感控件。TUI 操作面板要求系统与 tuios 能证明本地套接字两端的进程及面板身份，无法证明时拒绝启动。目标受保护或两条采集路径均不可用时拒绝采集；这两条采集路径及 Windows TUI 均尚未进行真实 Windows 桌面验收。
- 跨平台编译不能替代实际桌面测试；Linux 和 Windows 后端的真实可用性、安全行为及性能仍需在对应系统验证。

## 1. 目标与边界

Golder 提供内置的 `computer` 工具，让用户明确选择一个应用及其窗口，再由 Agent 在可观察、可暂停、可接管的条件下操作该目标。平台代码集中在独立的 `computeruse` 包中；它是 Golder 内置能力，不要求用户安装第三方 MCP 插件。

**首个版本同时支持 macOS、Linux 和 Windows**；macOS → Linux → Windows 仅表示实施和验证顺序及投入重点，不是分版本发布顺序。三平台都必须完成第 8 节的共同验收，平台差异和支持范围须明确记录。

第一版默认采用**单 App / 单窗口模式**：

1. 用户在 Golder 中选择 App 和窗口。
2. GUI 右侧展示该窗口；TUI 在终端支持图形时展示相同目标的画面。
3. Agent 优先使用窗口内的 Accessibility 元素进行语义操作。
4. 语义操作不可用时，才请求截图坐标操作。
5. 每次操作前检查目标窗口身份、窗口状态和该操作必要的焦点条件。
6. 目标关闭、焦点或窗口状态发生不安全变化时暂停。
7. 切换到其他 App 或窗口，必须重新获得用户同意。

单窗口是 Golder 的产品和策略约束，**不等同于操作系统已经提供强制的单窗口输入沙箱**。特别是鼠标和键盘注入可能受焦点、遮挡、窗口移动以及系统行为影响。不能可靠确认目标时应拒绝或暂停，而不是静默操作别的窗口。

不以 Computer Use 取代已有专用工具：网页优先使用 `browser` 的 DOM/可访问性 ref；文件编辑优先使用文件工具。桌面语义树与截图坐标用于专用接口无法满足的场景。

## 2. 统一架构

```text
                         用户
                          │
             ┌────────────┴────────────┐
             │                         │
         Golder TUI                 Golder GUI
       Kitty 图形协议              MyGo Bitmap
       独立 pane 展示和操作       右侧面板展示目标画面
             │                         │
             └────────────┬────────────┘
                          │
               Computer Use 会话控制面
         用户选目标 / 授权 / 状态 / 暂停 / 接管
                          │
                  内置 computer 工具
                          │
               独立 computeruse 核心包
          统一会话 / ref / 帧 / 坐标 / 操作接口
                          │
                  平台后端与系统接口
              macOS → Linux → Windows
```

TUI 和 GUI 共用能力模型、安全策略和平台后端接口，各自进程管理自己的会话；不要求两个前端隐式共享同一个正在运行的控制会话。Kitty 与 Bitmap 是**画面展示适配器**，不是桌面采集或控制后端。

首版优先在仓库内独立成包，例如 `internal/computeruse`，与 `internal/agenttool` 的内置工具注册、TUI/GUI 展示层分离。是否需要额外的首方 helper 进程，以及平台原生桥接的具体形式，须在 macOS 原型中结合权限、签名、打包、崩溃隔离和性能验证后决定；子进程本身不自动构成安全沙箱。

## 3. 平台能力与实施顺序

以下三个平台均属于首版交付范围，按所列顺序推进和验证，而非先发布 macOS、之后再发布其他平台。

### 3.1 macOS：优先实现，重点打磨体验

- **语义观察和操作**：使用 Accessibility / AXUIElement 访问用户选定应用及窗口内的可访问控件。支持时优先使用元素动作和设置值，不把所有操作降级为鼠标坐标。
- **窗口画面**：使用 ScreenCaptureKit 采集选定窗口，用于用户预览及按需提供给模型的截图。
- **输入兜底**：语义动作无法完成时，通过受控键鼠输入完成；执行前必须验证目标、坐标、焦点及窗口状态。
- **权限体验**：分别解释和检查 Screen Recording、Accessibility 等系统权限，以及 Golder 自己的目标授权。系统授权不等于允许 Agent 操作任意窗口。
- **用户体验**：GUI 自动展开 Computer 面板；TUI 支持图形时显示画面；两者均提供清晰的目标与暂停/接管状态。

为避免通过桌面工具绕过 pane 的人工授权边界，macOS 目标列表排除 Golder GUI、系统授权界面及部分已知终端宿主；终端操作应使用专门的 pane 工具。已知应用的排除列表不是对所有自定义宿主的完整识别。

应用无障碍实现质量不一：自绘画布、游戏、部分 Electron/Java/老应用可能只有不完整的语义树。截图坐标是必要兜底，但不承诺所有应用或系统受保护界面都可操作。

#### macOS 多桌面与生命周期

- 窗口发现覆盖当前用户会话中的其他桌面；先匹配已有窗口，再按本机已安装应用的规范路径匹配，以处理本地化名称不一致，避免因未看到已有窗口而重复启动。仅发现唯一应用时才允许启动；启动命令成功不代表进程由 Golder 新建，也不代表窗口已出现。
- 使用窗口号、PID、进程启动时间及应用路径绑定目标，以 AX 窗口几何唯一匹配校验；不同桌面的窗口位置可能相同，无法唯一确认时拒绝而非猜测。选择其他窗口仍需原有授权流程。
- 不为后台语义操作静默切换桌面或抢焦点：AX 观察和定向动作可尝试跨桌面使用；画面只采集经 PID/窗口号精确匹配的单一窗口，系统不提供时如实失败，不回退成整屏截图。坐标、按键和滚动仍须目标位于当前可见桌面、前台且无遮挡，无法证明时拒绝；不能承诺所有应用、最小化窗口和 macOS 版本都支持后台截图或输入。
- `close_window` 是可控会话上的显式动作，仅向已绑定窗口的 AX 关闭按钮发送关闭请求，不退出应用、不关闭其他窗口。动作须通过常规风险评审，派发成功不代表窗口已关闭；未保存提示由用户处理，发送后暂停会话，禁止自动操作新弹窗。`stop` 仍只撤销会话，不关闭窗口。即使 Golder 曾发起启动，也不能证明进程和其他窗口此前不存在，因此不自动退出应用。
- 验收覆盖其他桌面已有窗口、名称本地化、多个窗口/歧义、启动后窗口出现、已暂停及只读状态、关闭请求/未保存提示和保留其他窗口。真实 macOS 多桌面、不同版本的 ScreenCaptureKit 后台窗口行为及物理输入仍须在用户授权的桌面实测。

### 3.2 Linux：首版支持，重点验证桌面环境差异

- 语义访问候选：AT-SPI2。
- Wayland 画面候选：ScreenCast Portal + PipeWire；输入候选：RemoteDesktop Portal / EIS，均遵守用户和桌面环境的授权。
- X11/受控虚拟桌面可作为另一后端，但 X11 本身不等同于隔离边界。
- 分别验证 GNOME/KDE、Wayland/X11、不同 portal 后端和应用工具包；发布明确的支持矩阵，不笼统承诺所有 Linux 桌面一致。

### 3.3 Windows：首版支持，重点验证权限与窗口边界

- 语义访问候选：Microsoft UI Automation。
- 窗口画面候选：Windows Graphics Capture。
- 键鼠兜底候选：`SendInput`，遵守 UIPI、完整性级别和系统受保护界面的限制；不绕过提权或安全桌面保护。

三平台统一产品语义、目标绑定与安全策略；可支持的系统动作和权限体验以各平台实际能力为准。交叉编译不能替代真实系统上的端到端测试。

## 4. GUI 入口与交互

在 GUI **右上角**增加一个 **Computer Use 单色小图标按钮**，与现有 Browser 按钮保持一致：

- 只显示紧凑图标，不使用彩色图标或大按钮；图标跟随当前主题颜色。
- 提供清晰的无障碍名称 `Computer Use` 和提示文字；图标本身不作为状态的唯一表达。
- 用户点击后进入目标选择或打开当前 Computer 面板；不得因点击图标或 Agent 请求就静默取得屏幕/输入权限。
- 用户选定目标并启动会话后自动展开右侧面板；关闭面板与停止会话的语义必须明确区分。
- 面板显示目标 App/窗口、会话状态、当前控制者，并提供 **暂停、人工接管、恢复、停止**。
- 与现有 Files、Changes、Browser 抽屉保持一致的互斥/切换体验，不同时挤占右侧空间；具体图标形状和排列顺序在实现时与现有布局协调。

## 5. TUI 展示与降级

在 tuios 工作区内，Computer Use 使用**独立 pane**展示和操作，与 Agent 对话 pane 分开；由 Golder 管理该 pane 的身份与生命周期，不由模型通过 shell 自行启动或接管。用户可在 pane 中查看目标及状态、暂停/接管、恢复和停止；人工操作必须明确区分于 Agent 输入，不能因打开 pane 而扩大原有授权。没有可用的 tuios pane 时，应明确提示并提供安全降级，不能假装已打开独立 pane。

支持 Kitty Graphics Protocol 的终端中，使用该协议展示同一目标窗口的画面；运行时检测能力，不只凭终端名称判断。已有浏览器 pane 的展示思路可以复用，但其 CDP、DOM、tab 和浏览器 socket 语义不能直接当作桌面控制后端。

不支持图形协议时，不让控制面完全失效：至少展示目标信息、会话状态、语义快照摘要、暂停/停止和人工接管提示。其他图像协议或外部预览属于后续可选增强。

## 6. 内置工具与观察—操作循环

提供一个跨平台、职责明确的**窄内置工具** `computer`；具体 schema 在实现前根据现有工具约定确定。它只面向当前已授权的 Computer Use 会话和目标窗口，不提供任意 shell、文件管理或通过模型指定系统句柄直接控制其他窗口的能力；网页操作仍优先使用 `browser`。不为每个平台或动作分别注册一组工具。候选动作：

| 动作 | 职责 |
|---|---|
| `status` | 返回目标、能力、权限和暂停状态 |
| `snapshot` | 获取目标窗口语义树和短期 ref |
| `screenshot` | 在授权范围内获取目标窗口截图 |
| `click` | 优先对 ref 执行语义动作；必要时使用坐标 |
| `fill` | 对支持的文本控件设置值 |
| `press` / `scroll` | 受控键盘或滚动输入 |
| `close_window` | 请求关闭当前授权窗口；不退出应用，派发后暂停 |
| `pause` / `stop` | 暂停或结束会话 |

目标选择及授权最终由用户控制。Agent 可以提出目标需求，但不能自行把授权从一个窗口扩展到另一个窗口。

用户可以直接用自然语言提出操作 App；TUI 和 GUI 在当前回合结束后处理 `computer_request`，按应用名精确匹配已发现窗口。唯一匹配自动启动单窗口观察与控制；macOS 无匹配窗口时会查找已安装应用、按应用身份再次匹配已有窗口，并在没有已有窗口且应用唯一匹配时请求打开。多个应用或窗口匹配时由用户选择；未找到应用时可选择现有窗口或取消。取消、中断和会话切换不得继续启动。用户也可继续手动使用 `/computer` 或 GUI 图标。

### 6.1 动态暴露能力

根据会话、授权状态及平台实际能力，动态收窄提供给模型的工具说明和可用动作：

| 状态 | 模型可见能力原则 |
|---|---|
| 未启用 Computer Use | 不向模型发送可观察或控制的 `computer` 定义；具备本地交互界面且策略允许时，可提供仅能请求用户选择的 `computer_request`。 |
| 已启用，尚无授权目标 | 可查询状态、请求用户选择目标；不暴露实际观察或输入能力。 |
| 目标已授权观察 | 暴露 `status`、有界 `snapshot`、按需 `screenshot` 等已获得授权且平台支持的观察能力。 |
| 目标已授权控制 | 在观察能力之外，按平台和当前授权范围暴露支持的语义动作及输入动作；坐标兜底仍须通过安全检查。 |
| 已暂停或人工接管 | 不执行 Agent 输入；用户明确恢复前不得自动重新开放控制。 |

用户选择目标、同意授权、人工接管与恢复始终由用户控制；模型对 `pause` 或 `stop` 的请求只可减少权限，不得自行恢复或扩大范围。动态 schema 是减少歧义和上下文开销的辅助手段，**不是安全边界**：每次调用仍须在执行时重新检查授权、目标身份、平台能力、暂停状态和审批结果。实现时验证 OpenAI、Anthropic、Gemini 等 provider 的动态工具定义及调用/结果协议兼容性。

### 6.2 观察—操作循环

```text
用户选择目标 → 语义 snapshot → 优先 ref 操作
                       ↓ 语义能力不足
                 获取截图 → 请求坐标操作
                       ↓
                 重新观察并验证结果
```

语义 ref 由 Golder 管理，绑定会话、目标和快照；控件失效或 UI 重建后返回 `stale_ref`，要求重新观察，不接受模型任意构造系统句柄绕过目标限制。

macOS 的定向 AXPress 和非安全字段 AXValue 设置不向当前前台应用注入鼠标或键盘，因此不以目标拥有前台焦点作为必要条件：每次动作仍须重新验证已授权窗口、进程身份、节点属于该窗口、安全字段和动作可用性。坐标、键盘等全局输入不适用此例外，必须在注入前单独验证焦点、遮挡和坐标映射。

截图及坐标动作应关联会话、目标、帧标识、尺寸、比例和采集时间。目标身份、窗口尺寸、位置、焦点或坐标映射不再满足操作前提时，拒绝旧操作并重新观察。高 DPI、多显示器、缩放及 GUI/TUI 预览中的 letterbox 坐标转换均须测试。

macOS 的物理输入代码使用一次性、短期帧标识；执行前重新捕获并比较画面，验证目标仍在前台、位置和大小未改变、输入点未被遮挡且 AX 命中非敏感的明确控件。无法确认时拒绝并暂停，画布或不完整无障碍树可能因此无法使用坐标兜底。按键限定为无修饰键的白名单，滚动距离受限；系统事件派发成功不等于应用已响应，必须再次观察验证。这些原生输入路径仍需要在目标机器上实测。

### 6.3 上下文与数据预算

内置工具或单工具门面本身不保证低 token 消耗；预算须分别覆盖工具定义、语义树结果、发送给模型的截图以及多轮动作历史：

- 工具定义保持简短，避免按平台复制 schema；按上述会话状态动态暴露必要能力。
- 语义快照默认仅包含当前授权窗口内可见、相关的可交互元素，并限制节点数、深度、单项文本和总输出字节；支持按条件缩小查询及分页/继续读取。截断必须明确标记，敏感控件值不得返回。
- Kitty 和 Bitmap 的**本地预览帧仅供用户展示**，不因刷新预览自动发送给模型；模型截图必须按需请求并限制尺寸、字节数及授权范围，必要时可在授权范围内请求局部或更高分辨率观察。
- 语义观察足够时不强制发送截图；动作返回简洁且真实的结果，失败、超时与截断不得隐藏，不无条件重复返回完整树或截图。
- 旧截图和历史的裁剪、压缩须兼容各 provider 的消息协议和 Golder compaction，保留工具调用与结果配对，不让模型误把旧观察当作当前状态。
- 用实际 provider 请求与 usage 测量未启用、只读、可控制等状态的 schema 开销，以及快照、截图和多轮任务的上下文成本；图片计费依模型/provider 而异，不预设固定 token 数。

## 7. 安全、隐私与接管

1. **默认关闭、显式启用**：Agent 不能自行授予屏幕读取或桌面控制权限。
2. **观察与控制分别说明**：读取屏幕也可能暴露隐私；向模型发送截图应清晰告知用户。
3. **持续可见的目标与状态**：让用户知道正在观察/控制哪个窗口，并能随时暂停或停止。
4. **单一控制者与串行输入**：同一目标的 Agent 输入应串行；用户接管时停止 Agent 输入，恢复需要用户明确操作。
5. **敏感流程由用户接管**：密码、验证码、系统权限对话框等不得由 Agent 自动绕过或代为确认。
6. **高后果操作确认**：购买、发送、上传、删除或其他难以撤销的动作应按现有权限机制请求确认；不确定时从严处理。
7. **屏幕内容不可信**：窗口中的文字和图像不能授予权限或覆盖用户指令，需防范提示注入。
8. **截图最小化**：限制尺寸、数量与保留时间；不默认持续录屏，不将原始画面和敏感输入写入普通日志。
9. **新窗口不自动授权**：目标 App 弹出新窗口时，应识别并请求用户确认；同进程或同 App 不自动代表同一授权范围。
10. **不夸大隔离能力**：Golder 的窗口校验、权限提示和进程拆分不能被宣传为已验证的 OS 级单窗口隔离；平台约束做不到时应如实提示。

## 8. 第一版验收

- macOS、Linux、Windows 均可由用户选择目标 App 和窗口；拒绝授权时不启动观察或控制。每个平台的已验证桌面环境、版本及限制须随首版记录。
- GUI 右上角提供与 Browser 风格一致的单色 Computer Use 小图标；启动后右侧展示窗口及明确的控制状态。
- 支持 Kitty 图形协议的 TUI 可展示目标画面；不支持图形时仍可查看状态并暂停/停止。
- 三个平台的标准控件分别可通过 AX、AT-SPI2、UI Automation 快照、ref 和语义动作完成代表性操作；不支持的控件可经过安全检查使用坐标兜底。
- 目标消失、变化、焦点不安全、过期 ref 或过期画面时不会继续执行旧操作。
- 切换应用/窗口、新窗口加入范围及从人工接管恢复都需要用户明确确认。
- 验证未启用、无目标、只读、可控制、暂停和人工接管等状态的动态能力暴露；尝试调用未暴露或已撤销的动作也必须在执行层拒绝。
- 验证语义树与截图的边界、截断提示、敏感值处理，以及本地预览不自动进入模型上下文；记录各 provider 下工具定义、观察结果和多轮任务的实际预算测试结果。
- 测试覆盖目标绑定、状态转换、ref 生命周期、坐标映射、超时与取消；首版须分别在真实 macOS、Linux 和 Windows 桌面环境上完成权限、窗口、输入和接管的端到端验证，不能用交叉编译代替。
