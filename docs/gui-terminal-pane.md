# GUI 项目终端与 Agent 控制

本文记录已确认的 GUI 终端方案。GUI 使用 MyGo 终端，不依赖 tuios 运行或管理 GUI pane；TUI 现有 tuios 功能不变。

> 实施中：右侧面板、项目布局和标题栏菜单已有基础实现；GUI Agent 终端工具和授权尚未实现，本文的验收条件不代表已经通过。

## 目标与入口

- 在主界面右上角 Browser 图标之后增加终端图标，显示或隐藏右侧终端面板。隐藏面板不终止终端进程。
- 面板及其分隔线可拖动调整；右键菜单提供向右、向下拆分、重命名和关闭。拆分可嵌套，每个 pane 有独立的 PTY、终端状态和稳定身份。
- 复用 MyGo terminal 和 split 组件；PTY 跟随视图大小调整，普通 shell 及全屏终端应用应能正常输入和重绘。
- pane 标题栏菜单提供拆分、重命名、关闭和授权操作；终端内容区保留 MyGo 原生的复制、粘贴、全选和清屏菜单。

## 鼠标行为

- pane 标题栏右键打开该 pane 的 Golder 菜单；面板中提供可见提示，帮助用户发现入口。
- 终端内容区保持 MyGo 原生鼠标与右键菜单行为；程序接管鼠标时事件交给程序。内容区 Ctrl+右键不保证打开 Golder 菜单。

## 项目、会话与生命周期

- 终端 pane 和布局按项目管理。同一项目切换聊天会话不会关闭进程或重置布局；切换项目时保留原项目终端并显示目标项目终端。
- 用户创建的 pane 属于项目；Agent 创建的 pane 还记录所属 Agent 会话。其他 Agent 会话不会因为同属一个项目自动获得权限。
- 用户可通过右键选择项目中具体的活动 Agent，明确授权其查看和/或控制用户创建的 pane，查看和输入的授权分开；可撤销或明确转交。写控制同一时间至多属于一个 Agent，用户接管时避免与 Agent 输入交错。
- pane 标题展示名称、运行状态和控制归属。授权绑定稳定 pane 身份与 Agent 会话，不随焦点、项目或聊天切换转移，关闭 pane 或会话结束后失效。
- 关闭运行中的普通 pane 前确认，确认后结束其进程。附着现有 Agent bash TTY 的 pane 关闭时只解除附着，不能隐式终止原 Agent 命令；终止是单独且明确的操作。
- GUI 退出前若仍有运行中终端须确认，退出后结束 GUI 所管理的终端进程；不启动后台守护或恢复原进程。可以恢复布局，但不默认保存终端输出或敏感内容。

## Agent 工具与安全边界

- GUI 向 Agent 提供 GUI 专用 `terminal` 工具，按稳定 pane ID 列出、读取有限输出、创建、拆分、聚焦、调整、关闭和交互，并以事件驱动方式等待输出与进程事件。
- “打开终端 / 新建终端”等未明确指定外部应用的请求默认使用内置 `terminal` 工具和 GUI 终端面板，不走 `computer_request`。仅在用户明确指定系统终端应用时才考虑外部应用，并遵循 Computer Use 的目标限制；内置终端受限或创建失败不能作为绕过授权、自动改开系统终端的理由。普通非交互命令仍使用 `bash`。
- 用户终端默认私有：读取也需要明确授权；Agent 输入用户终端会在用户终端的环境运行，不可宣传为已在 Agent 沙箱中。
- Agent 创建与输入必须经过既有信任、权限、路径、网络和执行环境边界，不能把一次性授权扩大为持久终端权限。工具调用审查时绑定 pane 身份，授权后再次校验身份与状态；不同 pane 可独立并发，同一 pane 输入须串行化。
- 终端输出属于不可信数据，内容不会变成授权指令。输入到用户 pane、销毁进程等操作不能绕过权限确认。
- GUI 的主 Agent、项目重建/恢复以及子 Agent 都不因继承 TUIOS 环境而暴露 `tuios` 与 tuios 专用 `workspace` 工具或误导性的 tuios `/pane`。TUI 继续使用既有工具；`bash`/`write_stdin` 和已有 TTY 附着功能保持可用。`--no-tools` 等工具禁用策略仍然生效。
- 不将 GUI 的 pane 或权限冒充为外部 tuios pane；`workspace` 原有的浏览器组合编排不是本功能的隐式承诺。

## 验收

1. 在 GUI 中创建、左右及上下拆分多个真实终端，独立输入，拖动分隔线并验证 PTY 尺寸；`vim` 等全屏程序与普通 shell 的键盘、鼠标和重绘可用。
2. 验证标题栏右键的 pane 操作与可见提示；终端内容区的原生菜单和程序鼠标接管不受影响。
3. 验证同项目会话切换、项目切换、隐藏面板、关闭 pane、附着 TTY 与退出 GUI 的进程生命周期。
4. 验证不同 Agent 会话的查看、输入、独占、撤销、转交，以及失效/重建后不能误用授权；普通用户终端的控制不得绕过审批和沙箱边界。
5. GUI 在带和不带 TUIOS 环境变量的启动方式下都只暴露正确的工具；`--no-tools` 和子 Agent 的工具策略不会被绕过，TUI 原行为不回归。
6. 用自动化测试覆盖可测试的状态、权限及路由；在支持的桌面平台验证真实终端交互。不能执行的手动或平台测试须明确报告。
