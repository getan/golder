# Browser review evidence, containment and session binding

## Target-directed review

Browser locator mutations collect bounded evidence before the permission gate:
browser/tab/target identity, page URL, original locator, match count, document
snapshot identity, explicit snapshot truncation, up to three candidates and two
ancestors. The reviewer receives this separately from the capped transcript;
the tool-result transcript budget is unchanged. Input values and fill/type
payloads are not target evidence.

This is read-only observation, not automatic approval. Page labels and ancestor
text remain untrusted data, even when they look like instructions. Runtime and
ownership facts are generated by the host and cannot be supplied as model args.
Evidence is bound to the prepared tool/arguments and cannot stand in for a
different call. Paused verification stops observation without retries.

Immediately before input, the tool rechecks the binding, URL, document, target
and locator evidence. Accessible/ref locators are lowered to the exact reviewed
ref, retaining the browser host's stale-document protection. CSS locators are
checked for uniqueness and document/content changes; raw HTML is hashed, never
included in review text. This is not a browser-side atomic transaction: the
current v1 host contract does not atomically bind arbitrary CSS execution to a
review token. Prefer stable refs for sensitive actions.

## Containment is not ownership

Guard failures distinguish `browser_not_owned`, `browser_socket_mismatch`,
`browser_policy_changed` and `browser_outer_sandbox_unavailable`. Diagnostics
include record presence, socket/policy match, backend envelope and whether
sandboxing was requested or enforced, without exporting socket credentials.
Reviewer source/level remain in the existing per-call review notes.

Both auto and ask consult the actual target's outer-sandbox capability, not just
the tool name. A running native browser cannot be moved beneath an outer OS
sandbox by marking the call contained. An unsatisfied containment requirement
fails closed; `host_control` is not a workaround. Actual external browsers still
need the same exact one-call host authorization, and policy/socket mismatches
cannot be laundered through that grant.

## GUI conversation changes

Same-project new/resume paths update the controller and tools to the same new
binding alongside the session identity, including read-only resumes. Old A/B
observations are rejected after A → B → A. This does not restore agent ownership
from workspace metadata or grant a read-only session input authority.

## Locator arguments and execution phase

`exact` is forwarded for locator operations, including click/fill/select. It is
rejected on actions where it has no meaning rather than silently ignored.
Exact matching does not remove real nested/duplicate matches.

Local preflight rejection can assert `not_dispatched`. A host error can assert
that phase only with explicit `locator_resolution` metadata bound to the
requested target; an error code alone is insufficient. Older hosts without
phase metadata, timeouts and transport failures remain outcome-unknown. No
mutation is automatically retried.

Regression coverage uses the same protocol fixture for native-GUI and isolated
TUI envelope shapes, including >1000-character snapshots, ambiguity, document
reloads, parent/target changes, malicious labels, pauses and session switches.
It does not claim a live Chromium or Feishu permission-change end-to-end test.
