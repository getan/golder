# 优先修复内置浏览器兼容性，在不增加外部人工操作的前提下提高自动化完成率

Author: Golder
Last updated: 2026-11-07
Status: 实施中；以下背景保留方案提出时的版本基线
Discussion: 本次关于百度、Google 风控与内置浏览器自动化的讨论；尚未关联 Issue。

## 实施时发现的版本变化

方案编写时固定的是 kitty-browse v0.2.8；当前 Golder 已升级至 v0.2.9，后者已提供类型化 `SendOperatorInput` 和兼容 JSON 方法，Golder 原本的动态类型断言已经能够注册后者。因此，下文“v0.2.8 缺少该能力”的分析是历史基线，不再代表当前实际运行路径；不能把本次改造称为首次接通 v0.2.9 的人工输入。

目前已将 Golder 改为通过类型化适配器调用该能力，移除旧 host 的 JS 指针事件降级，并为输入队列增加有界合并和显式拒绝。代理透传的 kitty-browse 源码变更位于 `.golder/crossrepo/kitty-browse`，尚未发布为可由 Golder 锁定的依赖版本，GUI 原生 host 因此仍会拒绝代理。其他方案项及端到端验证尚未完成。

## Abstract / 摘要

我们提议先修复可证实的输入、运行时、会话与网络配置问题，再用受控实验判断哪些因素影响站点访问。一期继续使用 Golder 内置浏览器，正常任务尽量自动完成，不要求用户打开另一浏览器、复制资料或额外登录。可选的外部浏览器人工接续放在二期，不作为一期依赖。

**提高正常任务的自动化完成率，不等于保证自动通过第三方验证码。** 一期减少可避免的误触发和交互失败；遇到真实验证码、访问限制或已锁存的 `browser_paused`，保留现有暂停边界，返回明确结果，不自动破解、重试挑战或切换身份绕过限制。任务不必强制转入人工流程，但必须诚实报告未完成。

本文记录原始方案和上述实施状态；尚未执行真实站点验证。

## Background / 背景与动机

### 用户看到的是一个问题，工程上必须拆成两类

当前反馈是：内置浏览器访问百度、Google 时容易触发验证，即使在面板里拖动图形，也可能失败。

需要区分：

1. **为什么进入验证页？** 可能涉及站点策略、访问频率、会话、网络出口、运行时特征。没有服务端风控原因或对照实验，不能判定主因。
2. **为什么面板里的操作不能正确送达？** GUI 的输入路径存在确定的兼容性缺陷，普通拖动、Canvas 和 iframe 也会受到影响。这不需要借助真实验证码才能复现。

修好第二类问题，不证明第一类问题已解决。二者必须分别统计和验收。

### 当前依赖是 kitty-browse v0.2.8，不是上一版分析使用的 v0.2.7

本次以 `go.mod` 锁定的 `github.com/getan/kitty-browse v0.2.8` 为依据。运行中的旧 Golder 或旧浏览器进程可能不同，后续诊断应报告实际版本，而不是只报告仓库依赖。

已确认的代码事实：

| 事实 | 证据位置 | 能说明什么 |
|---|---|---|
| GUI 使用截图展示的 headless Chromium host | `gui/cmd/golder-gui/browserhost.go` 的 `Start`；依赖 `browserhost/host.go` 的 `DefaultOptions` | 面板可见不代表底层是 headful Chromium |
| GUI 只有 host 满足 `BrowserOperator` 才注册原生人工输入通道 | `gui/cmd/golder-gui/browserhost.go`；`gui/appsession/browseroperator.go` | 接口存在不等于运行时能力已接通 |
| v0.2.8 中未实现 `SendOperatorInputJSON` | 依赖 `browserhost.Host` 及该版本源码 | 当前链接的原生 host 无法满足此接口，GUI 会落入兼容分支 |
| 兼容分支通过 `eval` 调用 `dispatchEvent(new MouseEvent(...))`，释放时还可能调用 `e.click()` | `gui/appsession/browsersurface.go` 的 `dispatchInput`、`pointerScript`、`pointerActivation` | 不是浏览器原生输入分发；JS 构造的鼠标事件不可信，也不完整 |
| 输入队列容量为 128，满时返回成功但丢弃事件 | 同文件 `Input`、`runInputs` | 不只 move，down/up、文本、按键也可能丢失 |
| Agent 的 locator 点击已有 CDP 输入路径 | 依赖 `internal/browser/automation.go` 的 `dispatchClick`、`pointer` | 不能说所有 Agent 点击都在用 JS 合成事件 |
| 底层已有 CDP 鼠标 down/move/up | 依赖 `internal/browser/session.go` | 可复用，但需要 host 接口、来源鉴别和集成测试 |
| GUI 原生 host 拒绝非空 `ProxyServer`，底层 `LaunchOptions` 支持显式代理 | `gui/cmd/golder-gui/browserhost.go`；依赖 `internal/browser/launch.go` | 配置链路存在断点；不能把配置值视为实际出口 |
| 默认 profile 已按项目持久化并复用 | `internal/agenttool/browser_profile.go`；[browser-sharing.md](browser-sharing.md) | 不是每次打开都丢 Cookie，不应重复实现“持久 profile” |
| 初始化做了 UA / Client Hints 处理，并保留真实版本信息 | 依赖 `internal/browser/identity.go`、`launch.go` | 并非完全没有身份一致性处理；效果仍需测量 |
| 当前视口使用 `EmulateScale(1)` | 依赖 `internal/browser/session.go` 的 `SetViewport` | DPR=1 是已知实现选择，本身不证明异常或风控原因 |
| GUI 把页面逻辑视口直接设成抽屉大小 | `gui/mygoui/browserpreview.go` 的 `bounds`、`surface.Resize`；依赖 `SetViewport` | 面板较窄时，页面看到的是窄视口，与桌面窗口浏览不是同一布局条件 |
| 启动链路没有显式语言/时区设置 | kitty-browse v0.2.8 的 `launch.go`（无 `--lang`、`Accept-Language`、`TZ`） | 页面语言来自进程环境；Finder 启动的 GUI 可能得到与用户地区不一致的默认值 |
| 验证或限流会暂停后续自动变更，恢复需明确确认 | [browser-sharing.md](browser-sharing.md)；依赖 `internal/host/interaction.go` | 新增通道不能成为绕过暂停的后门 |

### 上一版方案方向部分成立，但因果结论和优先级需要修正

| 上一版说法或建议 | 复核结论 | 本方案处理 |
|---|---|---|
| JS 合成鼠标事件是硬伤 | 成立，属于确定的输入兼容性问题 | 一期修复，但不承诺因此通过验证 |
| 因 `isTrusted=false`，所以本次验证码失败 | 前半句成立，后半句尚无站点证据 | 用本地事件测试证明缺陷，不替站点推断判分规则 |
| 百度滑块一定只监听 pointer 事件 | 未验证，且组件、版本可能不同 | 覆盖通用 pointer/mouse 语义，不依赖某家验证码内部实现 |
| 主 frame 的 `elementFromPoint` 无法把事件分发到跨域子文档 | 成立，兼容分支无法正确完成该类输入 | 单独覆盖 iframe/OOPIF；改用 CDP 不代表任意 frame 自动正确 |
| CDP `isTrusted=true` 等价于真人输入 | 不成立；浏览器生成事件与真实人类行为不是同一概念 | `isTrusted` 只作为本地事件来源测试，不作为风控通过条件 |
| headless 必然空 plugins、SwiftShader、无焦点 | 不能概括所有 Chromium 版本和机器，本次未测 | 记录实际值，禁止作为既定事实或硬编码修补目标 |
| Mac 的 DPR=1 必然指纹矛盾 | 不成立；显示设备、缩放和远程环境都影响 DPR | 检查坐标一致性，不强制伪装成 Retina |
| 高频截图会直接累计站点风控分 | 无证据；截图是本地 CDP 操作，不等于新的站点请求 | 按 CPU、延迟、交互卡顿优化，不宣传为降低风控分 |
| IP 是首要原因，代理可立竿见影 | IP 可能重要，但未定位，代理也可能更差 | 修正用户已配置的网络路由，不自动换出口、不使用代理池 |
| 复制日常 Chrome 资料解决会话问题 | 不采纳，违背专用 profile 隔离且有加密/锁冲突 | 只复用现有 Golder 项目 profile |
| 先首页、逐字输入、停留一下能保证降低风控 | 无通用保证，也可能增加请求和复杂度 | 只在页面正常工作流需要时采用，不做“养号”与拟人表演 |
| 优先切 headful | 不是一期默认方案，会引入窗口及跨平台复杂度 | 一期比较运行时兼容性；额外窗口人工接续留到二期 |

`Event.isTrusted` 表示事件由浏览器生成，而非脚本 `dispatchEvent` 生成，不是“真实人类”的认证。MDN 的定义见附录。我们不修改该属性来伪造事件来源。

## Design / 设计

### 1. 一期不改变用户操作入口，正常流程仍由 Agent 自动完成

一期目标：

- 默认打开同一项目的既有受控浏览器，不新建一次性身份。
- Agent 的常规导航、定位、点击、输入、等待继续自动执行；修正工作流错误和无谓的重复请求。
- 若用户本来就在内置面板操作，其输入应正确到达同一标签页；修复这条通道不新增用户任务。
- 自动执行本地兼容性回归与非敏感运行时诊断，不要求用户手动跑检测网站。
- 用户配置一次浏览器网络设置后，GUI 与 TUI 的后续启动应一致，不逐页要求人工干预。

一期非目标：自动解验证码、自动产生验证码轨迹、打码服务、代理或 profile 轮换、读取个人 Chrome 资料、关闭 Chromium 沙箱，以及新增外部浏览器人工接续。

若站点明确拒绝当前自动访问，一期允许任务以 `blocked` 结束并保留浏览器状态。最大化自动化不应变成无限重试，或把失败隐瞒成成功。

### 2. 自动化动作与人工输入共享底层机制，但不能共享授权来源

建议链路如下：

```text
Agent 工具调用
  → 现有权限与目标检查 → 暂停/交互检查 → 有界动作调度 → CDP

内置 GUI 已发生的用户输入
  → 进程内 BrowserOperator → 目标/文档检查 → 有界输入队列 → CDP

CDP → Chromium 页面 → 现有截图链路 → 内置面板
```

两条路径复用事件分发和坐标转换，不复用“人工来源”权限。不得提供一个模型可填写的 `human=true` 参数；也不能把 Agent 请求转发到 `BrowserOperator` 从而绕过 `browser_paused`。

kitty-browse 只增补类型化的进程内输入能力（如指针、按键、文本方法），不解析 Golder 的 JSON 信封。Golder 用一个薄适配器把这些方法实现成 `BrowserOperator`，JSON 契约继续留在 GUI 侧，避免库反向依赖应用格式。不要仅为 GUI 人工事件新增一个不受暂停检查的公共 socket 动作。

如普通自动化拖动确有新增需求，它属于独立的 Agent 动作：必须进入现有 schema、权限、暂停和目标校验，不因与人工输入共用 CDP 就自动获得人工身份。

### 3. 先修输入语义和队列，不制作“拟人化”轨迹

#### 3.1 将 GUI 的 JS 兼容输入替换为浏览器输入分发

- down/move/up、悬停、按键、提交文本走 host 的 CDP 能力，让 Chromium 负责命中测试和派生 DOM 事件。
- 不再由 Golder 手工补发 `click`、`pointer*`、`mouse*` 来拼凑事件序列，防止重复点击。
- 记录输入能力探测结果。新版原生 host 缺少 operator 能力时应在测试中失败，在产品中明确报告降级，不能静默宣称“原生交互可用”。
- 旧外部 host 保持可观测和正常 Agent 动作兼容；是否保留其基础 JS 点击由兼容开关决定，但不能把它报告成完整拖动或跨域输入能力。
- 分别测试主文档、同源 frame、跨域 frame、OOPIF、滚动后的坐标和遮挡场景。无法证明目标时返回 `unsupported_frame` 或目标失效，不猜测输入。

#### 3.2 down/up、文本与按键不能在队列满时静默丢失

将 FIFO 改为有界、分类型的队列：

- move/hover 可合并相邻待处理采样，只保留该段最新位置；不得跨越 down/up、按键、切页等屏障合并。
- down/up、文本、按键与取消是边界事件。为它们预留容量或进入显式拒绝/取消流程，不能入队失败仍返回成功。
- 压力过大时拒绝启动新手势；已开始的手势要在原目标上完成释放或明确清理，不能遗留按下状态。
- 保留已有输入的顺序和可用时间信息；不补造人类轨迹、随机抖动或随机点击时长。
- 记录排队时间、合并数量、拒绝原因和完成状态，不记录输入内容。
- 失败后不自动重放可能已执行的 down、click、submit。执行状态未知与“未发送”必须区分。

手动拖动的触感改进来自减少阻塞与正确交付，不来自固定插值到 60–120Hz。刷新频率应以性能测量决定，不能把人为补点当修复。

#### 3.3 截图像素、CSS 坐标和文档身份必须一致

目前 GUI 以截图尺寸反算输入坐标，底层 DPR 固定为 1。这个假设要显式化：

- 每帧关联 browser/tab/target、CSS viewport、截图像素尺寸、有效缩放和视口修订号；不把图片像素默认当作 CSS 像素。
- 输入基于其对应帧转换，viewport 变化、导航或切页后旧帧输入应拒绝，而非投到新文档。
- 手势从 down 到 up 绑定同一目标和文档版本；关闭、取消、失焦、切页都进入清理流程。
- 拖动期间布局变化不重新解释旧坐标；测试清理动作不会落到新页面。
- 限制重复 `set.viewport`，只在尺寸实际变化后更新；避免截图和 resize 相互干扰。
- 页面逻辑视口应有桌面下限（例如不小于 980 CSS px）或明确配置，而不是始终等于抽屉宽度；位图按比例缩放到面板，输入做精确反变换。代价是窄面板里文字变小，可用缩放或“实际大小”视图补偿，具体值由基线测量后确定。

#### 3.4 按输入语义选择键盘接口，不把中文强拆成逐键输入

保留 `insertText` 处理已提交的 IME 文本、粘贴与普通文本写入。导航键、组合键和确实依赖键盘事件的普通控件使用按键接口。需要 composition 的控件另设兼容性测试。

Agent 的 `fill/type/press` 选择依据控件语义和已知兼容性，不依据“越像人越好”。不把逐字延迟设为所有文本输入的默认要求，也不承诺因此通过验证。

### 4. 自动化可靠性优化必须落到 Agent 实际使用的路径

GUI 鼠标链路修复能解决现有面板缺陷，但单独完成它不会改善所有无人值守任务。因此一期同时检查：

- locator 动作执行前的可见、可操作、遮挡和文档版本检查；沿用底层现有校验，不重复造另一套点击器。
- 用页面事件、目标元素和导航结果等待替代频繁 reload 或盲目固定 sleep；读取快照与截图不构成新权限。
- 同一 tab 的变更动作串行执行；共享 profile 的多 Agent 不在同一文档交错输入。人工输入与变更动作的冲突保持可见且有界。
- 动作只在能证明“尚未发送且可安全重试”时重试。提交后超时先返回未知状态，不再点击一遍。
- 不强制所有搜索都先访问首页；控件依赖初始化状态时按站点正常导航进入，否则保留有效直达能力。

若任务只是获取公开搜索信息，可以在任务开始时按已有或单独批准的搜索服务能力选路，浏览器留给必须交互的网页。它不是一期强制新服务，不默认增加凭据配置，也不能在某站点暂停后被用来继续访问同一受限资源或绕过限制。

### 5. 修通网络配置，不自动更换网络身份

在 kitty-browse 的 `browserhost.Options` 增加显式代理配置并传给现有 `LaunchOptions.ProxyServer`；Golder 原生 host 传递已验证的 `NativeBrowserRequest.ProxyServer`。仅删除当前拒绝分支还不够，依赖层也需要扩展并发布版本。

约束：

- 不继承任意环境代理变量，不把代理凭据放进 argv 或日志。
- 配置非法或代理不可达时明确失败，不悄悄改成直连。
- 已运行浏览器保留其启动网络配置；修改设置只影响下次正常启动，不能在请求中间改变路由。
- `status` 区分配置值、已确认的启动模式和未知的实际出口。`--proxy-server` 只能证明配置，不能证明出口 IP 信誉；系统 VPN/透明代理还可能影响流量。
- 测试使用本地受控代理与回显服务确认请求实际经过代理，不默认向第三方 IP 检测服务发送数据。
- 不选购“住宅 IP”、不做出口轮换、不在触发挑战后自动切代理。

这是修复 GUI/TUI 行为不一致，不是“代理能解决风控”的承诺。

### 6. 保持专用会话连续性，避免重复创建身份

默认项目 profile 已持久化；一期主要增加回归和运行时证明：

- 重开、Agent 会话切换、GUI/TUI 接续均使用既有项目 identity；有活动进程时复用，不重开竞争同一 profile。
- Cookie、Local Storage、IndexedDB 的持久化用本地虚拟账户测试，不读取真实 Cookie 或导出到模型。
- macOS 保持 basic password store、mock keychain 与原有 profile 加密兼容；不能只换启动方式而忽略 Cookie 可读性。
- profile 缓存清理规则不得误删登录状态；不为实验扩大组件下载或后台存储规模。
- 不跨项目共享登录身份，不复制个人 Chrome profile，不通过预访问、伪造历史等“养 profile”。

新项目仍可能是新会话，这属于现有隔离的代价，不以自动导入个人资料消除。

### 7. 先做运行时兼容性基线，不堆叠指纹伪装

一期保留内置 headless 形态，比较完整 Chrome/Chromium 的统一 headless 与已安装 `chrome-headless-shell` 的兼容性、稳定性和资源成本。它们不是同一种运行时；不能把 headless shell 的现象推广到完整 Chrome。

仓库 [browser-runtime.md](browser-runtime.md) 已记录过 macOS 完整 Chromium 的截图超时，以及特定 headless-shell 版本的截图可用性。新选择必须同时满足截图、输入、会话、沙箱和退出要求，不能为了某站点表现牺牲基本功能。

建议记录实际版本、运行时类型、有效非敏感 flags、语言/时区来源、viewport/DPR、图形后端和身份覆盖模式。仅在本地 fixture 检查 HTTP UA 与页面暴露值、Client Hints 是否按当前实现保持一致。

语言与时区应来自可解释的系统设置，而不是环境偶然值。当前启动链路没有显式设置，Finder 启动的 GUI 可能落到 en-US/UTC 一类默认值，与用户实际访问的站点地区不一致。我们提案读取系统区域设置，以 `--lang`、`Accept-Language` 和时区显式传给浏览器，并在 `status` 中报告生效值；不做随机化，也不为了匹配某站点而改写成别的地区。

一期不：

- 伪造插件、Canvas、WebGL 或硬件品牌；不随机化 UA、DPR、时区。
- 把 `webdriver=false`、某检测站得分或 `isTrusted=true` 当作可通过百度/Google 的证据。
- 因为 UA 写着 Mac 就强制 DPR=2，或强制启用 GPU/关闭安全功能。
- 自动下载新浏览器、静默换内核；尤其不能在站点阻断后切运行时继续尝试。
- 随机切换语言、时区或地区来匹配 IP 或站点。

若比较证实某运行时更兼容，应作为后续明确的默认选择提案；一期的选择仍通过既有可信设置在启动前固定。所有比较在不引入额外用户窗口的模式下进行。

### 8. 截图调度优化服务于交互延迟，而非未知的风控得分

目前 GUI 约每 150ms 尝试获取一帧，实际速率还受截图耗时限制。优先测量 CDP 排队、CPU、解码、帧龄和输入延迟，再决定是否合并截图、降低静态页刷新或使用受控帧流。

输入边界事件优先于冗余截图；隐藏面板降低无用刷新。DOM 读取、截图和输入不能因调度调整而改变权限。观测减频不能成为漏报暂停或误判动作完成的理由。

### 9. 让自动化知道什么时候停止，而不是自动弹出另一个浏览器

对任务执行器提供结构化的阶段与错误分类，具体字段在实施时与现有 API 对齐：

| 分类 | 处理 |
|---|---|
| `ready / action_completed` | 按任务继续 |
| 输入能力缺失、目标失效、frame 不支持 | 不猜测、不重放；返回具体失败位置 |
| 导航或提交结果未知 | 保留状态，停止依赖该结果的后续动作 |
| 普通瞬时传输失败，且确定未发送 | 允许有界重试，记录原因和次数 |
| `rate_limited / captcha / browser_paused` | 停止自动变更，保留现有暂停，不自动刷新、换页、换身份或恢复 |

站点提示可能被误识别。暂停检测的改进应在可控 fixture 上区分隐藏组件、正文提及验证码与可见挑战，不应以删除检测或自动 resume 降低“阻断率”。HTTP 429 与 `Retry-After` 可作诊断，但不能覆盖已锁存的显式恢复要求。

没有可用自动路径时，返回“未完成，站点要求验证/限流”的结果；一期不强制拉起人工流程。用户若已选择在内置面板处理，原来的交互入口仍保留；自动恢复仍须遵守现有确认机制。

### 10. 默认诊断只采集必要事实，不抓取用户秘密

诊断分三层：

1. **启动事实**：依赖/实际浏览器版本、输入能力、启动模式、profile 逻辑 ID、网络配置模式、沙箱状态。
2. **本地 fixture**：事件顺序、坐标误差、受控 frame 的实际收件人、队列压力、会话恢复和代理路由。
3. **经许可的站点小样本**：导航阶段、首次出现阻断的步骤、任务是否完成。不得把真实验证码作为反复尝试的测试夹具。

默认不打开外部指纹网站，不记录完整输入、账号、Cookie、授权头、代理凭据、完整查询 URL 或挑战 token。截图与 DOM 诊断附件只在明确开启时保存，并采用有界、脱敏、可清理的存储。诊断日志优先放在 checkout 外的私有 Golder 目录；给模型返回能力摘要，不返回敏感资料。

## Rationale / 理由与取舍

### 我们先修可复现的兼容性问题，而不是承诺反风控

输入丢失、错误事件来源和主 frame JS 命中限制都有代码证据，并能在本地复现。站点风控模型没有这样的可见性。先修确定缺陷，能改善正常页面和既有用户操作，也让之后的实验少一个干扰项。

收益必须分开看：GUI 人工输入修复主要改善已有面板；Agent 动作可靠性、会话复用、网络配置与运行时兼容性才直接影响无人值守完成率。不能用前者替代后者验收。

### 这里的“自动化”指减少自身失败，不是自动通过验证码

如果把这轮目标理解成“让滑块每次自动通过”，本方案不满足，也不应承诺。那需要伪造行为轨迹、识别缺口或接入打码服务，既缺少稳定依据，也违反站点条款并与现有暂停模型冲突。

我们优化的是另一件事：不让 Golder 自己的输入丢失、错误事件来源、窄视口、环境地区漂移、网络配置断点或运行时兼容问题，把本来正常的任务推进验证页；受阻时给出可解释的结果。这两件事的验收方式完全不同。

### 我们不选择通用拟人化补丁作为主线

随机等待、补造鼠标轨迹和伪造指纹缺少可验证的因果依据，会增加任务时延、脆弱性和排障成本。它们也可能被用于规避站点验证。我们保留浏览器真实能力，修复 Golder 引入的不一致，不试图制造另一台机器或另一个人的身份。

### 一期不依赖外部人工浏览器，接受明确的自动化边界

额外窗口、人工登录和个人资料迁移会违背本次的产品要求，也增加 profile 加密、锁和身份风险。因此一期不采用它们。代价是：真实挑战仍可能使任务无法自动完成；任何架构都不能凭这些改动保证站点接受自动访问。

二期若有业务需求，再评估用户自愿启用的 headful/外部接续，届时另行设计授权、窗口可见性和 profile 生命周期；不预先把这些复杂度放进一期。

## Compatibility / 兼容性

- `BrowserTool` 的现有动作和暂停语义保持不变；不新增“人工身份”模型参数。
- Golder 与 kitty-browse 需要配套升级并锁定发布版本；不依赖开发者本地 sibling checkout 或永久 `go.work replace`。
- 同进程新 host 在启动测试中强制校验 operator 能力；外部旧 host 返回明确能力不足，不能在挑战时偷偷选择兜底通道。
- operator 适配器位于 Golder；kitty-browse 不依赖 Golder 类型或 JSON 格式，双方只约定类型化的输入方法。
- 新增网络字段使用显式配置，默认行为与现有直连启动一致。旧版本不支持时清晰报错，不自动忽略用户配置。
- 沿用项目 profile 布局、目录权限、锁和 macOS Cookie 加密约定。不进行 Cookie 迁移或个人资料导入。
- 拖动坐标链路变更必须在 DPR=1/2、缩放、滚动、嵌套 frame 下回归；暂不只为模仿显示设备修改 DPR 默认值。
- TUI 的原生输入能力已有实现，应复用机制并验证不回归，而非将其改成 GUI 的旧 JS 路径。
- Chromium 自身沙箱和现有浏览器专用运行权限不能弱化；新增能力不扩大到任意宿主文件或外部浏览器。

## Implementation / 实现与过渡

### 一期按证据推进，运行时更换不是默认前置条件

| 顺序 | 工作 | 主要范围 | 交付条件 |
|---|---|---|---|
| P0-A | 实际能力与版本基线、错误分类 | Golder status/host；本地测试 | 能区分 GUI/Agent 输入路径、运行时、网络配置与真正的站点阻断 |
| P0-B | operator 接通、队列与手势状态修复 | kitty-browse host/session；Golder BrowserSurface/MyGo | 不用 JS 构造事件兜底完整输入；边界事件可靠；目标不漂移 |
| P1-A | Agent 动作串行、等待与未知结果处理 | 既有浏览器动作/任务策略 | 正常页面能自动完成，不靠重复点击和刷新 |
| P1-B | GUI 代理配置闭环、profile 持久化回归 | kitty-browse Options；Golder launcher/profile/status | 路由测试与现有存储/加密/锁测试通过 |
| P1-C | 运行时与截图调度比较、低频真实观察 | 本地 fixture、已安装运行时；可选许可站点 | 给出测量结论和是否值得独立调整默认值的建议 |
| P1-D | 逻辑视口下限、语言/时区显式来源 | Golder GUI/status；kitty-browse 启动参数 | 面板尺寸不再等于页面窗口；页面语言/时区与系统一致且可诊断 |
| 二期 | 可选 headful/外部人工接续 | 另行设计 | 非一期依赖，不以此替代一期自动化验收 |

P0-B 无法只靠 Golder 补丁完成：控制协议没有 raw pointer/drag，底层能力在 kitty-browse 内。发布顺序应为 kitty-browse 先提供类型化输入与测试，再升级 Golder 依赖并发布桌面包；旧 host 只保留明确的降级。

P0-A、P0-B 合入后先验本地兼容性，P1-A/B 验证后再判断真实任务完成率；P1-C/D 先产出测量值和默认值提案。本文不授权立即执行这些实现步骤或修改另一个仓库。

### 自动化测试先覆盖普通交互，不拿验证码做回归靶场

必须覆盖：

1. **真实 host 接线**：使用发布依赖启动的真实 `Host` 满足 operator 能力，不能只有 fake operator 测试通过。
2. **原生事件与来源**：本地页面记录 pointer/mouse/input/key 顺序、按钮状态和实际目标；检查 CDP 路径的事件行为，不以此认定真人。
3. **主文档/iframe/OOPIF**：受控多源 fixture 内输入到指定控件，遮挡、导航中断和失效目标均明确拒绝。
4. **压力与取消**：大量 move 混合 down/up、文本、键盘；队列满、取消、失焦、断连、切页后无静默丢失、无粘键、无跨目标残留。
5. **坐标和帧龄**：DPR、缩放、留白、滚动、resize 和旧帧失效；断言最终控件状态，而非仅收到 CDP 成功响应。
6. **正常自动任务**：无挑战的搜索框、提交、导航、等待、弹层和文件选择等任务；对动作日志检查无重复提交。
7. **隔离与会话**：本地虚拟登录重启可恢复，跨项目不共享；并发 profile 锁、生存期、退出清理与已有 GUI/TUI 用例通过。
8. **网络闭环**：本地显式代理收到预期请求，非法/不可达配置不回落直连；日志不含凭据。
9. **暂停不能绕过**：可见挑战 fixture、当前文档 429 与显式暂停阻断所有新 Agent 变更；新增 operator 只能由既有 GUI 用户输入调用，不能通过模型或 socket 冒用。
10. **运行时稳定性**：截图可解码且有正确内容，反复导航/resize/输入不崩溃，CPU/内存和正常退出可接受。
11. **视口与地区**：窄面板下页面仍按约定的逻辑视口布局，位图缩放与坐标反变换精确；页面语言/时区显式生效，不因 GUI/TUI 或启动方式不同而漂移。

真实浏览器、PTY 或本地 socket 在沙箱内不可用时，应明确 skip/未验证，不声称集成测试通过，也不为测试关闭安全边界。

### 先定指标，再讨论“优化了多少”

以下是拟定验收目标，不是当前已测成绩：

| 指标 | 目标或比较方式 |
|---|---|
| 本地确定性普通交互用例 | 全部通过；关键场景重复运行，无跨文档输入和重复提交 |
| 队列边界事件 | 压力用例中零静默丢失；拒绝、取消、未知结果均有记录 |
| 人工来源隔离 | Agent/socket 冒用 operator 的测试全部拒绝 |
| 暂停边界 | 暂停后无新自动变更，无自动恢复、刷新或换身份 |
| 输入响应延迟 | 对固定参考机器统计入队至 CDP 完成 P50/P95、最长排队时间；初定目标 P95 < 100ms，基线测量后校准并单独报告高负载 |
| 正常任务完成率 | 使用相同 fixture 和相同任务集比较修改前后；业务验收阈值在基线建立后确认 |
| 真实站点首次挑战率 | 仅在许可范围内记录分子/分母、运行时、会话条件、网络配置、时间段；小样本只作观察，不宣称因果 |
| 实际挑战通过率 | 不是一期自动化验收指标；不以重复挑战来优化 |
| 外部人工步骤 | 一期新增步骤为 0；受阻任务报告未完成，不自动弹外部浏览器 |

站点观察一次只改变一个因素，保持版本、任务、访问规模和网络条件尽可能一致，区分首次访问与复用会话。profile 本身会积累状态，时间也会影响站点策略，因此简单 A/B 不能自动推断因果。出现挑战即停止该轮自动动作，不能用更多尝试补样本。

### 每项变更能独立回滚，但不能回滚安全边界

operator、队列、网络接线和截图调度分别设置灰度/能力开关。新通道故障时允许禁用面板输入并返回不支持，不能自动转向绕过暂停的 JS 执行。运行时选择在浏览器正常启动前固定，回退要求先释放 profile；站点阻断本身不是切换运行时的触发条件。
