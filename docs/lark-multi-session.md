# Lark 多会话连接与登录状态串行化

## 用户可见行为

同一台机器、同一个 `GOLDER_HOME` 下，多个 GUI 聊天、多个 TUI，以及 GUI/TUI 同时运行，
可以复用同一来源的 Lark/Meegle 登录状态。**不需要为了普通查询去断开其他空闲会话。**

- `Connect / probe` 成功后，来源可显示 `on demand`：工具目录已就绪，但空闲时没有常驻
  helper 持有登录目录锁。这不是断线，也不是要求重新登录。
- 每次业务调用按需启动一个经过审阅的 `golder-lark`，完成后关闭该次 helper。
- 同一来源的实际操作串行执行。已有操作使用登录状态时，后来的调用在自己的超时预算内等待，
  并可取消；等待期间不会启动本次 CLI，也不会偷偷重放请求。
- 登录态仍位于 `$GOLDER_HOME/extensions/mcp-lark/home`。不会复制 token 到每个聊天目录，
  不会读取用户全局飞书登录，更不会把凭据交给模型。

这是“多个会话可用、实际状态访问串行”，**不是同一账号下所有业务请求完全并行**。
Lark 与 Meegle 是同一个来源的两个服务，因此也共享这把状态锁。

## 原先为什么会报占用

原实现为持久状态来源在子进程启动时获取排他锁，并保持到进程退出。MCP stdio 连接是常驻的，
于是一个空闲聊天只要连接过 Lark，就可能一直占住锁，让另一个聊天的普通文档搜索报：

```text
extension state is in use; disconnect its other session before setup/reset
```

这不是飞书账号、文档权限或扫码授权的单会话限制，而是宿主把连接寿命与状态访问寿命绑定了。
新实现保留跨进程锁，只缩短已知 Lark helper 的占用范围。

## 锁和生命周期

1. 逻辑连接保存该会话已审阅的配置、工具目录和生命周期，不在空闲时持有文件锁。
2. 目录探测、业务调用以及显式状态检查，都必须先取得该来源的跨进程排他锁。
3. 等待可取消；拿到锁后重新检查来源是否仍启用、审批和程序/依赖指纹是否仍匹配。
4. 以同一个私有 HOME、原来的网络/OS 沙箱上限启动一次 helper；业务派发前再次验证工具 schema。
5. 精确调用的 policy/operator 确认元数据原样传递；一次业务操作只派发一次。
6. 正常结束或取消后，关闭该次 MCP 连接并等待 helper 排空、退出，再释放锁。
   如果退出暂未确认，仍保留锁直到实际退出；不能因为超时或 socket 消失就让另一个写者进入。

锁文件在 HOME 外的持久父目录：

```text
$GOLDER_HOME/extensions/mcp-lark/.lock
$GOLDER_HOME/extensions/mcp-lark/home/
```

重置只删除 `home/`，不能替换正在使用的锁文件。所有会话和进程协调的是同一个锁 inode。
排队时间计入调用/探测预算，不保证严格 FIFO；慢请求可能让后来者等待或超时。

## 授权、重置和取消

- `setup` 和 `reset` 仍是显式用户操作，保留排他保护；它们不会与进行中的查询、写入或
  token 刷新同时修改/删除同一份状态。
- 其他会话只是空闲逻辑连接时，不会阻挡授权或重置。
- 有实际操作或旧版常驻连接正在占用时，授权/重置会拒绝进入，而不是打断对方或删除锁文件。
- 等待中取消/超时属于 **not dispatched**，不会被误报为已经执行过的未知写入。
- 已派发后的取消、传输失败或退出未确认，仍可能是未知执行结果。宿主不自动重试业务调用，
  尤其不能自动重放写入。先检查回执/实际数据，再决定后续动作。
- 重置影响共享这份登录状态的所有会话，但不等于撤销飞书服务器端授权；下次使用可能需要
  用户重新授权。不要用 reset 修复连接排队。

## 升级与适用范围

本次是宿主的连接/资源管理改动，不改变 helper 的工具或登录格式，也不要求为此清空登录态。
已运行的旧版 GUI/TUI/helper 不会自动获得新生命周期：**升级后要断开或正常退出旧的常驻连接一次**。
可在占用的旧 TUI 中执行 `/mcp disconnect lark`；不是退出飞书账号，不需要删 token 或重新安装。

该策略仅用于 `state_dir=true`、stdio、可执行文件名为 `golder-lark` 的已审阅来源，别名来源
仍有各自独立的状态目录。其他第三方 MCP/RPC 的状态访问可能有后台行为，不会被自动改成短连接；
它们继续遵守原有生命周期和独占规则。远端 HTTP MCP 不使用这一本地状态锁。

## 验证范围

回归测试使用临时私有 HOME 和模拟 MCP/CLI，不连接真实飞书账号：

- 两个独立 Manager 可以保持逻辑连接，空闲时锁可释放；业务访问不会重叠或丢失模拟刷新写回。
- 不同宿主进程通过同一锁文件协调；等待可取消，取消的调用不启动 helper。
- 等待期间撤销/指纹变化，以及重启后的 schema 变化，会阻止派发。
- 活跃业务阻止 reset；其他空闲连接不阻止 setup/reset；来源目录和隔离边界不变。
- 子进程退出未确认时不会提前释放锁，也不会自动重试未知结果。

Linux 容器预检仍暂停；平台测试、真实账号登录与远端业务结果要分别报告，不能用本地模拟替代。
