# 通过 Tailscale 控制 Golder 当前会话

> 目前完成了本地开发和自动化测试，**尚未在真实 Tailnet、iPhone 或 Android 上验收**。以下是后续手动验证的准备说明，不表示已验证你当前的 Tailscale 环境。

此功能让手机浏览器控制 Mac 上**明确开启远控时选定的一个 TUI 或 GUI 会话**：查看最近的会话内容、发送文字、回答支持的审批。Mac 仍运行 Agent 和原有权限／沙箱；手机不直接运行 shell。

## 连接与安全边界

```text
手机浏览器 ── HTTPS / WSS，经 Tailscale ──> Mac 上的 Tailscale Serve
                                                   │ HTTP，仅本机回环
                                                   ▼
                                        Golder 127.0.0.1:18787
```

- 不需要公网端口映射，也不使用 Tailscale Funnel。TLS 终止于 Tailscale Serve；Serve 到 Golder 的最后一段是本机回环 HTTP，不能称为进程间端到端 TLS。
- Golder 在启动时读取本机 Tailscale 状态，并定期重新检查。信息无法验证、路由变化或配置不符合要求时拒绝／停止远控；不会回退到普通局域网 HTTP。运行中的检查有时间间隔，并非对配置变动的瞬时拦截。
- 每次启动生成短期一次性配对码。手机扫码后，需在 Mac 核对并允许，手机也要确认核对码；凭证仅用于当前服务实例。停止服务、Golder 退出或重启后，需要重新配对。
- 同时只允许一个共享会话和一个手机连接；手机可以看到该会话中传输的代码、工具输出和审批，请不要把二维码分享给他人。安全仍依赖你的 Tailnet 访问策略、Mac 和手机本身的安全。

## 前置条件

1. Mac 与手机连接到允许两者互访的 Tailnet；Mac 的 Tailscale 已登录，并开启对应的 MagicDNS／HTTPS 能力。
2. Mac 上的 `tailscale` CLI 可以被 Golder 找到；具体 macOS 安装版本和 CLI 可用性尚需在你的机器上验证。
3. 预先由你配置一个**专用、仅 Tailnet 可访问的 HTTPS Serve origin**，其根路径 `/` 代理到 `http://127.0.0.1:18787`。Golder 只读取配置，不自动创建、覆盖或删除 Serve 路由。
4. 现阶段校验较保守：拒绝启用的 Funnel、无法识别的配置、Tailscale Service／前台 Serve 配置、同一 origin 的其他路由，以及共享 Golder 回环端口的其他可识别路由。现有无关配置也可能因此需要先调整；不要用全局 `reset` 来绕过检查。

例如，在确认 `8443` 没有被已有 Serve 配置使用、并确认你愿意新增这条路由后，可由你自己参考 Tailscale 当前 CLI 帮助配置：

```text
tailscale serve status --json
tailscale serve --bg --https=8443 http://127.0.0.1:18787
```

**不要直接运行第二条命令而不先检查现有配置**：它会改变 Tailscale 配置，端口冲突可能影响其他服务。此示例没有在你的环境执行或验证，具体命令和可用端口以你安装的 Tailscale 版本为准。结束 Golder 远控不会删除这条 Serve 配置；如不再需要，由你检查后只移除自己创建的专用路由。

## TUI

1. 在空闲的完整 TUI 会话输入 `/remote-control`。启动过程先验证 Serve 配置。
2. 二维码在**仅操作员可用的私有浏览器 pane** 中显示，不写入普通对话记录。该路径目前依赖 Golder 的内置浏览器和可用的 tuios 私有授权 pane；普通独立终端若无法提供该 pane，会安全失败，不会把二维码降级打印到终端。
3. 手机扫码并启动配对；回到 Mac，比较双方的短码。输入 `/remote-control approve <短码>`，或输入 `/remote-control deny` 拒绝。
4. 手机上点击代码一致，连接当前会话。使用 `/remote-control status` 查看状态，使用 `/remote-control stop` 停止服务。

配对期间不会启动新的 TUI 操作。远端文字中的 slash 命令、`!` shell 命令和本地图片引用会被拒绝；运行中的输入可能被拒绝而不是排队，手机应保留草稿并由用户决定是否重试。

## GUI

1. 等待 GUI 中所有 Agent 会话空闲，在目标会话顶部点击 **Remote → Start remote control**。
2. 在私有配对期间，GUI 暂停新 Agent turn；手机扫码后，在 Mac 的弹窗中核对手机名称和短码，再选择允许或拒绝。
3. 手机上确认代码一致。标题栏显示 **Remote ●** 表示远控服务处于启用状态；再次打开 Remote 可停止。

切换 GUI 标签不会让手机悄悄控制另一个会话。若原 controller 被关闭或会话身份改变，远控停止或拒绝后续操作。

## 审批、重连和限制

- 手机目前提供符合条件的 **Deny / Allow this call once**，并显示原请求的摘要和能力范围；不会从手机创建长期记忆授权。无法完整表达的能力（包括 host-control 和浏览器运行时例外）仍须在 Mac 上处理。
- 本地和手机针对同一请求只能有一个有效答案；断线时已向手机展示且可远程回答的待决问题按未回答处理，不把断线记成持久拒绝。原有静态拒绝、权限模式、trust 和 sandbox 不因手机连接而绕过。
- 当前协议使用有序的**完整状态快照**，保留有界短期快照历史；重连时可补发或重新同步。快照最多包含最近 200 个前端条目、约 120 KiB；界面会标记被省略的早期内容。这不等同于完整历史导出或每个内部事件的逐字节镜像。
- 工具卡片的投影目前并不对称：GUI 可显示工具输出；TUI 的手机视图目前只显示工具名称，不包含结果或 diff。这是仍待补齐的功能缺口。
- 不支持手机文件／图片上传、多会话切换、多个控制设备、原生 App 或手机端 shell。手机发送的 slash 命令会被拒绝；TUI 不接受远程本地图片路径。
- 发送后若网络中断，手机可能显示结果未知。**不要盲目重复具有副作用的操作**：先查看当前会话状态，再由你决定是否重新提交。
- 旧 REPL 的明文 LAN 远控入口默认已停用；旧协议不与 v2 共用配对凭证，也不会自动降级。

开发中的本地测试使用模拟配置和回环 WebSocket，不验证真实证书、Tailscale Serve 的实际转发、手机扫码、移动浏览器后台或跨网络连接。完成上述真机验收之前，请勿把该实现视为已通过生产安全验证。
