# PRD：GUI / TUI 全局 MCP 与 Lark 配置向导

状态：待确认。范围仅包含 MCP 与 Lark；CLI 启动更新由其他工作负责，不属于本需求。

## 1. 背景与目标

Golder 已支持 stdio 和 Streamable HTTP MCP，并提供全局 source 配置、命名凭据、审批、连接和工具发现。GUI 的 Settings → Extensions 能管理已有 source，且已有 Lark 专用配置界面；TUI 的 `/mcp` 可浏览和管理已配置的 source。两端目前缺少通用 MCP 添加向导，TUI 也缺少完整的 Lark 安装配置向导。

目标是让用户不必手动修改 TOML，即可通过 GUI 或 TUI 添加和管理全局 MCP，使用 Golder 内置浏览器完成远程 MCP 的通用 OAuth 和 Lark 授权，并以尽量少的输入配置 Lark，同时保留对第三方代码、网络和业务操作的明确授权。

配置范围已确认：**第一版新增的 MCP 为全局配置**。项目级配置及其覆盖优先级不在本期范围内。

## 2. 用户故事与验收标准

### US-001：通过 GUI 添加通用 MCP

作为 GUI 用户，我希望在 Settings → Extensions 中添加 MCP，以便无需编辑配置文件。

- [ ] 提供 Add MCP 入口，支持粘贴常见 `mcpServers` JSON、填写远程 URL、填写本地命令及参数。
- [ ] 可填写或修改合法的 source ID；重复 ID 不得静默覆盖。
- [ ] 预览显示连接方式、实际地址或命令与参数、网络权限及凭据引用；不支持的输入字段有明确提示，不静默丢弃。
- [ ] 用户可选择保存为禁用状态，或在审阅后批准并连接；保存禁用状态不得启动进程或连接网络。
- [ ] 连接成功显示工具数量；失败显示原因，并保留配置供编辑和重试。
- [ ] 手动验证桌面设置界面的添加、确认、取消及错误状态；相关自动化测试通过。

### US-002：通过 TUI 快速添加通用 MCP

作为 TUI 用户，我希望在 `/mcp` 中粘贴配置并完成添加，以便尽量减少手工操作。

- [ ] `/mcp` 列表提供 Add MCP server 和 Lark 配置入口。
- [ ] 新增向导支持多行粘贴 JSON、输入远程 URL、输入本地命令和参数。
- [ ] 单个无凭据的合法服务可经“添加 → 粘贴 → 审阅确认”完成连接；Esc 可返回或取消，取消不写入配置。
- [ ] 审阅页面显示实际执行或连接目标及权限，并提供保存禁用和批准连接两种操作。
- [ ] 针对 JSON 中多个服务，用户可逐项选择；重名项可跳过、改名或经明确确认替换。
- [ ] 手动验证终端键盘导航、多行粘贴和窗口缩放；相关自动化测试通过。

### US-003：管理全局 MCP

作为用户，我希望在 GUI 和 TUI 查看与管理已有 MCP，以便发现故障并控制启用状态。

- [ ] 两端均可查看已配置服务的名称、类型、状态和最近错误；支持测试、编辑、启用、禁用和删除。
- [ ] TUI 可浏览已发现工具；GUI 至少可显示工具数量及查看工具列表。
- [ ] 编辑导致命令、参数、地址或权限等信任边界发生变化时，旧批准失效，重新启用前须重新审阅。
- [ ] 删除需要用户确认；默认不删除可能由其他配置引用的命名凭据。
- [ ] agent 正在执行且不允许更改连接时，界面提示等待当前回合结束，不中途替换本轮工具集。
- [ ] 手动验证 GUI 和 TUI 的状态、确认与失败界面；相关自动化测试通过。

### US-004：安全处理 MCP 凭据

作为用户，我希望 Token 和 Secret 不进入会话或普通配置，以便降低泄漏风险。

- [ ] 手动输入的敏感值使用遮罩控件，不写入对话、提示词历史或普通日志。
- [ ] 保存时使用现有命名凭据机制；source 配置只保存凭据引用，不保存输入的敏感值。
- [ ] 导入时对常见敏感 Header 和环境变量给出默认识别建议，允许用户调整；无法保证识别所有秘密这一限制在预览中可见。
- [ ] 连接、导入失败和取消时，错误消息不包含输入的秘密；自动化测试覆盖已知敏感值。
- [ ] 取消或保存失败不留下无引用的新凭据；替换和清理不得破坏其他 source 使用的凭据。

### US-005：TUI Lark 向导

作为 TUI 用户，我希望从 `/mcp` 完成 Lark 配置，以便不手工编辑 TOML 或运行 `print-config`。

- [ ] 向导检测托管 helper 和官方 CLI，已完成的步骤自动跳过；检测不自动安装或授权。
- [ ] 缺少依赖时，显示组件、来源和版本，由用户确认后安装并校验。
- [ ] 输入 App ID 和遮罩的 App Secret；默认生成凭据名称。
- [ ] Lark 服务选择默认全部勾选，用户可取消不需要的服务；Project 为单独的可选项，仅选择时要求相关依赖、配置及单独授权。
- [ ] 启用前审阅程序、网络和服务范围；显示浏览器授权地址或验证码并等待明确结果。
- [ ] 测试只初始化和发现能力，不发送消息或执行其他业务操作；失败可重试。
- [ ] 手动验证 TUI 键盘操作、授权中断及恢复；相关自动化测试通过。

### US-006：简化现有 GUI Lark 配置

作为 GUI 用户，我希望现有 Lark 卡片按下一步引导我完成配置，而不需要重新配置已完成的部分。

- [ ] Settings → Extensions 保留 Lark 入口，按依赖、应用信息、服务选择、审阅、授权、测试展示下一步。
- [ ] 新配置的 Lark 服务默认全部勾选且可取消；已有配置按已保存选择显示，不因新默认值改变。
- [ ] 保留现有有效配置及登录状态；安装或配置失败后可以重试或取消，不静默覆盖用户配置。
- [ ] Lark 和 Project 授权状态分别显示；其中一项成功不得标记另一项成功。
- [ ] 继续沿用需用户确认的安装、来源校验、启用和业务工具审批。
- [ ] 手动验证桌面向导的状态转换、取消、失败及恢复；相关自动化测试通过。

### US-007：跨入口配置一致性

作为使用不同界面的用户，我希望 GUI、TUI 和命令行读取同一全局配置，并在冲突时保护已有设置。

- [ ] 新增或修改 source 后，当前进程通过现有 manager 更新，不要求重启当前进程。
- [ ] 后续启动的 GUI、TUI 和命令行读取相同全局 source 定义和凭据引用。
- [ ] 已运行的其他进程提供刷新方式或明确提示重新打开；不得声称自动实时同步。
- [ ] 并发写入或配置已被其他进程修改时，不静默丢失其他修改；冲突须提示并允许重新加载。
- [ ] 自动化测试覆盖跨入口读取、配置冲突、保留无关 TOML 及已有 source 兼容性。

### US-008：远程 MCP 通用 OAuth 授权

作为用户，我希望为需要 OAuth 的远程 MCP 在 Golder 内置浏览器中登录，以便不必手动复制 Token 或打开系统浏览器。

- [ ] GUI 和 TUI 在已审阅并同意连接的远程 MCP 需要 OAuth 时，显示授权服务的域名及已知权限范围，并由用户确认开始授权。
- [ ] 支持符合 MCP OAuth 规范的授权服务器和资源元数据发现、客户端注册或配置，以及授权码 + PKCE 流程；不宣称支持服务商特有的所有认证方式。
- [ ] 内置浏览器中的登录、验证及同意操作由用户完成；不调用系统浏览器，不让 agent 自动操作或读取授权页面。
- [ ] 回调仅接收本次授权事务，验证 state、PKCE 和重定向目标；取消、超时、拒绝或回调不匹配均不保存有效授权或显示成功。
- [ ] OAuth 授权成功后保存该 source 专属凭据，安全处理过期、刷新和刷新失败；需要重新授权时可从 source 详情发起。
- [ ] GUI 和 TUI 区分连接失败、需要登录、授权中、授权成功和已连接；浏览器不可用或服务商拒绝内置浏览器时，明确提示原因并允许取消，不自动切换系统浏览器。
- [ ] 测试覆盖元数据、回调和令牌交换错误，跨 source 隔离，令牌刷新，以及 Token、授权码和浏览器敏感内容不进入会话或日志。
- [ ] 使用可控 OAuth 测试服务手动验证 GUI 和 TUI 的成功、拒绝、中断及重试流程。

### US-009：授权浏览器的用户控制和隔离

作为用户，我希望在 Golder 内完成 MCP 和 Lark 授权，同时避免 agent 读取或操作我的登录页面。

- [ ] GUI 在 Golder 内提供用户可交互的授权浏览器界面；TUI 在可用的 Golder workspace 中提供授权浏览器 pane。
- [ ] 通用 OAuth 和 Lark 授权均不主动打开系统浏览器；Lark 若使用扫码协议，可在 Golder 内展示二维码并等待手机确认。
- [ ] 授权浏览器使用与普通 agent 浏览器隔离的临时身份，不导入个人浏览器资料或 cookies；成功、失败、取消后在浏览器退出时清理临时资料。
- [ ] agent 的浏览器、pane、截图和输入工具不能访问授权页面或授权 pane；登录、验证码和同意操作仅由用户执行。
- [ ] 没有可用内置浏览器、没有可见 workspace 或目标服务拒绝该浏览器时，显示具体失败状态及重试或取消；不得静默回退到系统浏览器或绕过验证。
- [ ] 自动化测试覆盖授权 pane 的访问隔离、事务结束清理和异常退出；GUI 与 TUI 授权窗口分别进行人工验证。

## 3. 功能需求

- FR-1：系统必须在 GUI Settings → Extensions 中提供通用 MCP 新增入口。
- FR-2：系统必须在 TUI `/mcp` 中提供通用 MCP 新增入口。
- FR-3：系统必须支持从常见 MCP JSON 导入 source，并在无法表示字段时明确提示。
- FR-4：系统必须支持以参数数组表示本地命令，不通过 shell 重新拼接执行。
- FR-5：系统必须在启用前向用户展示并确认 source 的执行或连接能力。
- FR-6：系统必须允许在不执行程序或连接网络的情况下保存禁用的 source。
- FR-7：系统必须将用户确认的敏感值保存为命名凭据，并在 source 配置中仅保存引用。
- FR-8：系统必须在 GUI 和 TUI 中提供已有 MCP 的编辑、测试、启停和删除操作。
- FR-9：系统必须在 TUI 提供基于现有 Lark 能力的安装、配置和授权向导。
- FR-10：系统必须在 GUI 继续提供 Lark 向导，并展示可恢复的下一步。
- FR-11：系统必须将新增 MCP 保存在全局配置中。
- FR-12：系统必须在配置被并发更改时防止无提示的更新丢失。
- FR-13：系统必须在 source 信任边界发生变化时撤销旧批准。
- FR-14：系统必须在初始化测试时避免调用业务工具。
- FR-15：系统必须为符合 MCP OAuth 规范的远程服务提供 OAuth 授权码 + PKCE 登录。
- FR-16：系统必须使用仅用户可操作的 Golder 内置授权浏览器完成通用 OAuth 登录。
- FR-17：系统必须对每次 OAuth 回调验证事务绑定，并对每个 source 隔离 OAuth 凭据。
- FR-18：系统必须支持 OAuth 凭据过期后的安全刷新或明确的重新授权。
- FR-19：系统必须使用 Golder 内置授权浏览器或内置二维码界面完成 Lark 授权，不主动唤起系统浏览器。

## 4. 非目标

- CLI 新版本检查与更新提示。
- 项目级 MCP 配置、项目覆盖与配置优先级。
- 保证兼容拒绝受控浏览器或使用非标准认证协议的所有服务商。
- 自动安装任意第三方 MCP、自动批准本地程序或远程服务。
- 绕过已有业务工具、沙箱或网络审批策略。
- 对已运行的所有独立进程承诺自动实时同步。

## 5. 设计与技术约束

- 复用 `internal/extensions` 的 source、配置、连接、指纹审批和 Lark 安装能力；GUI/TUI 共享业务服务，避免分别实现两套安全逻辑。
- 保持现有 `golder mcp` 命令、全局 TOML 和 Lark 配置兼容。编辑保留无关配置；进程内互斥不等于跨进程并发保护，需设计跨进程冲突检测或锁。
- 预览和审批必须反映即将实际执行的具体配置；配置或可执行目标发生变化后不得沿用过期批准。
- GUI 与 TUI 的密钥输入、回显、粘贴、日志与错误路径均需覆盖；导入识别仅为建议，不能保证发现任意自定义字段中的敏感内容。
- 网络、文件系统、安装及浏览器授权均为显式操作；保存禁用配置不得触发它们。
- 现有 Lark GUI 授权会打开系统浏览器；TUI 的隔离授权 pane 当前展示扫码页面，不是通用 OAuth 交互浏览器。需新增用户可交互的隔离授权能力，不能直接将现有实现当作已支持通用 OAuth。
- OAuth 只使用可信来源的元数据及安全的 URL、回调和重定向策略；授权码、PKCE verifier、Token、完整授权 URL 和浏览器页面内容不得进入模型上下文或普通日志。
- 界面状态区分已保存、已批准、已启用、连接中、已连接、授权失败和连接失败，避免以“已配置”冒充“可用”。
- 采用原生桌面 GUI 和终端 TUI 的实际交互验证，不以浏览器模拟替代桌面界面验证。

## 6. 成功标准与验证

- 用户可从 GUI 或 TUI 使用粘贴配置完成一个不需要凭据的 MCP 添加与连接，而不编辑 TOML。
- 用户可在 TUI 完成 Lark 向导，而不调用额外的配置命令。
- 用户可在 GUI 和受支持的 TUI workspace 中使用内置浏览器完成符合 MCP OAuth 规范的测试服务登录，不打开系统浏览器。
- source 配置、审批失效、重复 ID、并发修改、敏感值脱敏、失败恢复和跨入口加载均有自动化回归测试。
- 手动验证 GUI 与 TUI 的成功、取消、网络失败及授权中断路径。
